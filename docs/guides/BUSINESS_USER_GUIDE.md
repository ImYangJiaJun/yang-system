## 0. 先看这一页：三个系统、一条链路、一个网址

### 0.1 三个系统各管什么

| 在哪里 | 管什么 | 通常谁负责 |
|---|---|---|
| **本系统**（浏览器打开） | 外部数据源、审批派发配置、派发记录、账号与权限 | 业务管理员、系统管理员 |
| **飞书审批管理后台** | 审批定义（表单长什么样、走什么流程） | 企业审批管理员 |
| **飞书多维表格** | 业务数据表本身，以及表上的「提交」按钮 | 表格所有者、业务同事 |

一句话记住分工：**审批单的「样子」在飞书审批后台定，审批单的「什么时候发、发哪条」在本系统配，触发审批的「按钮」在飞书多维表格里点。**

### 0.2 一条完整链路（照这个顺序做）

1. 【运维/飞书应用管理员】在飞书开放平台建一个「企业自建应用」，开通权限、发布，并把应用加为多维表格的「文档应用」。
2. 【业务管理员】在本系统建「飞书数据源」，拿到每个字段的「接口地址」和「Token」。
3. 【审批管理员】在飞书审批管理后台建审批定义、设计表单；给单选/多选控件配置「使用外部选项」（填第 2 步的地址和 Token）；确认无误后**发布**，复制「审批定义 Code」。
4. 【业务管理员】在本系统建「审批派发配置」，拿到「派发链接」「访问 Token」和两份请求体模板。
5. 【表格所有者】在飞书多维表格里加一个「按钮」字段（或页面按钮），建一个「自动化」：按钮点击 → 发送 HTTP 请求到派发链接。
6. 【任何有表格编辑权限的同事】点按钮 → 本系统创建审批单 → 审批编号与状态自动回填到表格里。普通同事的日常操作见 1.7。

### 0.3 网址与浏览器

系统统一访问地址：`http://47.109.148.207:18654`

- **必须带 `:18654`**，并且目前**只能使用 `http`**（加 `https` 会打不开）。地址以管理员通知为准；复制链接时也不要自己把 `http` 改成 `https`。
- 支持浏览器：Chrome / Edge 111 及以上、Firefox 128 及以上、Safari 16.4 及以上。
- 明文 http 页面下浏览器有时会禁止网页自动写剪贴板：点「复制」没反应时，手动全选文本再按 `Ctrl/Cmd + C`。界面通常会把明文摊开给你选。

### 0.4 先认识几个词

| 词 | 白话解释 |
|---|---|
| 多维表格 / Base | 就是飞书里的多维表格。一条记录可以理解成表格里的一行。 |
| Base Token（app_token） | 多维表格地址里 `/base/` 后面那一段随机字符，相当于这张表的「门牌号」。 |
| 审批定义 Code | 审批模板的唯一编码，在审批后台编辑页的地址栏里，`definitionCode=` 后面那一段。 |
| 外部选项 | 审批表单里某个下拉框，选项不是手填的，而是从本系统的数据源实时取的。 |
| 回填列 | 表格里用来写「审批编号」「审批状态」等结果的列。系统处理完会往这里写。 |
| Token（两种） | 数据源「凭据配置」里的 Token 填进飞书审批控件；审批配置「接入数据」里的「访问 Token」填进飞书工作流。两者不通用。 |

## 1. 使用本系统：登录、账号、导航、权限（所有同事）

### 1.1 第一次登录

1. 打开系统地址，未登录会自动进入「用户登录」页。
2. **还没有账号**：点登录页右下角「创建账号」→ 填「帐号」「密码」「确认密码」→ 点「创建账号」→ 回到登录页看到「账号已创建，请登录」。
   - 帐号：3～64 位，只允许字母、数字、下划线、连字符（不区分大小写，系统按小写保存）。
   - 密码：10～128 位，不能与帐号相同，不能是 123456、password 这类常见弱口令。
3. **密码登录**：在「密码登录」页签，填「帐号」（用户名或已绑定的邮箱都行）和「密码」，点「登录」。
4. **验证码登录**（免密，需先在账号设置里绑定并验证邮箱）：切到「验证码登录」→ 填「邮箱」→ 点「发送验证码」→ 到邮箱找 6 位数字码 → 填入「验证码」→ 点「登录」。
5. **双重验证**：如果账号启用了动态验证码（手机认证器 App 生成的 6 位数，也叫 TOTP），密码通过后会弹出「双重验证」对话框，输入认证器里的 6 位数字（输满自动提交），或点「认证器不可用？使用邮箱验证码」。没有装认证器也可以走邮箱验证码。
6. 账号同时有「个人账户」和「系统管理」两种功能域时，会先到「选择本次使用的功能域」页，点「以系统管理进入」或「以个人账户进入」。功能域就是你这个账号能用的几套功能；普通同事一般选「个人账户」，选错可以退出重选。

> 登录失败提示「密码无效」不区分「账号不存在」还是「密码错」，这是安全设计，不要据此猜测账号是否存在。连续失败会被限流，提示「请求过于频繁，请在 N 秒后重试」。

### 1.2 进去以后怎么走

- 登录后落在「应用中心」：以卡片列出你能访问的模块（如「账号设置」「权限管理」「用户」「飞书数据源」「审批派发」），点卡片进入。
- 左侧导航最上方是「YANG System 控制台」，按功能域分组列出菜单；底部是「退出登录」。
- 顶部右侧可调「密度」（紧凑/默认/宽松）和明暗主题；窄屏时点左上「打开导航菜单」。

### 1.3 个人账号设置（左侧「个人账户 → 账号设置」）

页面上自上而下有这些区块：

| 区块 | 能做什么 | 注意事项 |
|---|---|---|
| 头像 | 上传头像 | 支持 PNG/JPEG/WebP/GIF，浏览器会自动压缩到 40KiB 以内 |
| 基本资料 | 查看账号信息 | — |
| 修改密码 | 填「当前密码」「新密码」「确认新密码」 | 新密码至少 10 位；成功后强制回登录页重新登录 |
| 修改用户名 | 填「新用户名」 | 成功后要用新用户名重新登录 |
| 绑定邮箱 / 更换邮箱 | 填新邮箱 → 发送验证码 → 填验证码 → 提交 | 成功后需重新登录；验证码 10 分钟内有效、60 秒后可重发、最多试 5 次 |
| 双重验证（TOTP） | 点「启用双重验证」，用认证器 App 扫二维码或手抄密钥，输入动态码 | **恢复码只显示一次**，必须当场保存；关闭双重验证需浏览器确认 |
| 登录设备 | 查看设备、IP、最近活动，非当前设备可点「退出」 | 换手机/怀疑被盗号时用 |
| 安全事件 | 查看「登录成功」「登录失败」记录及原因 | 排查异常登录 |
| 危险区 | 「停用账号」 | 停用后不能自助恢复，需要管理员启用 |

### 1.4 为什么我看不到某些菜单（权限）

**新注册的账号默认没有任何业务权限**，只会在左侧看到「个人账户 → 账号设置」。看不到「飞书数据源」「审批派发」不是系统坏了，是还没授权。

- 菜单是按权限「整块出现或整块消失」的，不会显示成灰色。直接输入网址也拿不到数据（安全兜底）。
- 管理员授权后，**你需要刷新页面或重新登录**才会出现新菜单。界面提示原文是「已授予，对方刷新会话后生效」。

管理员给同事开权限（三种方式，任选）：

1. **按用户**：「系统管理 → 权限管理」→「按用户」页签 → 搜索并选中同事 → 点「授予新权限」→ 在「授予权限」对话框里搜索并勾选权限（默认「永久有效」，也可选「过期日期」）→「确认授予」。
2. **按组（多人同岗位推荐）**：「权限管理 → 按组」→「新建权限组」，填「组标识」（小写字母开头，如 ops）、「展示名」（如 运维）、「描述」→ 在「权限条目」点「添加条目」勾权限 → 在「成员」里搜索并「加入所选成员」。
3. **按功能反查**：「权限管理 → 按功能」→ 左侧选一条权限 → 右侧看「直授持有者」「组持有者」，也可以点「给用户 / 组授权」。

常用权限与菜单的对应关系：

| 想看到 / 做什么 | 需要的权限 |
|---|---|
| 打开「飞书数据源」、查看数据源 | `feishu.datasource.read` |
| 新建、编辑、删除数据源 | `feishu.datasource.write` |
| 在数据源详情里复制 Token 明文 | `feishu.datasource.secret` |
| 查看选项数据 | `feishu.option.read` |
| 打开「审批派发」、查看配置与派发记录 | `feishu.approval.read` |
| 新建/编辑/启停/删除审批配置、轮换访问 Token | `feishu.approval.write` |
| 打开「权限管理」 | `access.grants.read` |
| 管理权限组 | `access.groups.write`（组所有者天然可管理自己的组） |
| 打开「用户」页 | `account.users.read` |

两个重要提醒：

- **管理员等价权限**：`feishu.approval.write`、`feishu.datasource.write`、`feishu.datasource.secret`、`feishu.portal.write`、`account.users.reset_credentials` 这 5 条，一旦给出就等于交出一部分系统管理能力（能签发凭据、能把数据公开出去、能重置他人密码）。系统会标红并要求勾选「我已知晓上述风险，仍要继续」，而且**只有内置组 `system_admin` 的成员才能授出**。
- **`system_admin`** 是系统内置的全权组，不能改、不能删，只能加减成员。全新部署里**第一个注册的账号**会自动成为管理员，之后注册的都是普通账号。

### 1.5 忘记密码、账号被停用

- **忘记密码**：系统没有「匿名自助找回」页面。找管理员在「系统管理 → 用户」页找到你，点「签发重置凭证」，把弹窗里那串字符给你（完整内容只显示一次，默认 15 分钟内有效、用一次即失效）。你在浏览器地址栏打开 `http://47.109.148.207:18654/reset-password`（前半段换成管理员给你的系统地址），把那串字符粘贴到「重置凭证」，设置新密码即可。
- **账号被停用**：登录会提示「未授权: 用户已停用」。控制台「用户」页目前只有「签发重置凭证」，没有「启用」按钮；找运维或系统管理员恢复，说明账号被停用了即可。

### 1.6 常见提示对照

| 你看到的 | 意思 | 怎么办 |
|---|---|---|
| 左侧菜单少了一大块 / 直接输网址进不去 | 没有对应权限 | 找管理员授权，然后刷新或重新登录 |
| 「密码无效」 | 账号或密码不对（不区分哪一个） | 核对账号；忘记密码走 1.5 |
| 「请求过于频繁，请在 N 秒后重试」 | 登录失败次数过多被限流 | 等待后重试 |
| 「凭据已变更，请使用新密码重新登录」 | 改过密码/用户名/邮箱或安全设置 | 用新凭据重新登录 |
| 「账号已创建，请登录」 | 注册成功 | 回登录页登录 |
| 「当前身份没有权限工作台的访问权限」 | 缺 `access.grants.read` | 找管理员 |

### 1.7 普通同事：提交一条审批与查进度（不需要本系统后台权限）

**提交前**：只要你能打开这张多维表格、能看到并点击行内的提交按钮，并且表格里这一行可以编辑，就不需要开通本系统的任何权限。看不到按钮或表格是只读的，找表格所有者。

1. 核对这一行的必填列。缺了必填内容时，系统不会创建审批，表格不会出现审批编号，你通常会收到一条飞书提示说明缺什么。
2. 点这一行的提交按钮。按钮名字由表格所有者设置，可能叫「提交审批」「发起审批」等。
3. 几秒后看这一行的「审批编号」列：出现编号 = 审批单已创建；出现一段文字 = 失败原因，按文字提示补齐或找业务管理员。
4. 你会在飞书收到一条结果消息：成功、等待或失败，消息里会写配置名、记录和下一步。

**查进度**：打开飞书「审批」→「我发起的」→ 找到这张单，能看到当前节点、审批人和是否通过。如果表格配置了「申请状态」「审批流程」列，也可以直接看表格汇总。两者都没有时，找业务管理员。

**查失败原因**：如果你看不到系统「派发记录」页，把这几样发给业务管理员：表格名称、这一行的内容或 record_id、审批编号（如果有）、点击按钮的时间、你收到的飞书消息截图。不要为了查原因去申请 `feishu.approval.write` 这类管理员等价权限。

**记住**：本系统不会自动扫描新记录，必须有人点按钮；点一次没成功可以补齐数据后再点，同一条记录不会重复建单。

## 2. 配置外部数据源：审批下拉选项从哪里来（业务管理员 / 运维）

### 2.1 三种来源，先选对

进入左侧「飞书数据源」（地址 `/feishu/datasources`），右上角「添加数据源」里有两条路：

| 类型 | 适合什么数据 | 怎么更新 |
|---|---|---|
| **多维表格**（最常用） | 数据已经在飞书多维表格里，且会经常变（如供应商、费用类型、银行网点） | 系统定时自动拉取（默认每 15 分钟一次，运维可调），也可手动「立即拉取」 |
| **文件导入** | 数据在 Excel 文件里（`.xlsx`），不常变 | 人上传；以后换数据用「重新导入」 |

另外还有两个相关概念：

- **对外查询门户**：不是第三种取数方式，而是建在任何数据源之上的一个公开查询页面（例如给外部人员查银行卡归属）。
- **手工推送**：旧版由多维表格自动化主动把选项推给系统的方式，新控制台**不提供创建入口**，只在存量数据里存在。新业务一律用「多维表格」或「文件导入」。

> 小提示：列表页空态的四步贴士里第 1 步「自定义 Token」是旧版说明；现在 Token 由系统生成，按 2.3 / 2.4 操作即可。

### 2.2 开工前准备（这一节交给运维 / 飞书应用管理员）

业务同事可以跳过，但配置前必须确认下面几件事已经做完：

1. **建飞书自建应用**：打开 <https://open.feishu.cn/app> → 「创建企业自建应用」→ 在「凭证与基础信息」复制 **App ID** 和 **App Secret**，交给运维写入服务端配置（`[feishu]` 的 `app_id` / `app_secret`）。**App Secret 不要发群、不要写进文档。**
2. **开通权限（scope）**，按用途组合：
   - 审批：`approval:instance`（创建实例）、`approval:approval:readonly` 或 `approval:definition`（读定义、订阅事件）、`approval:approval`（申请全量审批权限）。
   - 多维表格：`base:table:read`、`base:view:read`、`base:field:read`（或整体 `bitable:app` / `bitable:app:readonly`）；读写记录 `base:record:retrieve`、`base:record:update`。
   - 通讯录：`contact:user:search`、`contact:contact.base:readonly`、`offline_access`（姓名解析与用户授权必需）。
   - 消息：`im:message:send_as_bot`（给同事发结果通知）。
3. **发布应用**：「应用发布 → 版本管理与发布 → 创建版本 → 申请线上发布」，由企业管理员审核通过。**以后每次改权限都要重新发布才生效。**
4. **把应用加进多维表格**：打开目标 Base → 右上角「…」→「更多」→「添加文档应用」→ 搜索并添加这个自建应用。若 Base 开了高级权限，要给应用「可管理」权限，否则会出现两种表现：接口报 403 / `1254302 Permission denied`，或「调用成功但返回空数据」。
5. **确认可用范围**：应用可用范围要包含会收到审批消息的同事，否则消息发不出去，系统里会显示「未通知」。

### 2.3 新建一个多维表格数据源（4 步向导）

**第 1 步：填写名称与 Base**

- 左侧「飞书数据源」→ 右上「添加数据源」→ 选「多维表格」。
- 填「名称」（给人看的名字，1～100 字）；在「Base Token（app_token）」粘贴多维表格链接。系统接受整条 `/base/` 链接（形如 `https://<租户>.feishu.cn/base/<app_token>?table=tbl…&view=vew…`），会自动拆出 Base、数据表和视图。
- 知识库 `/wiki/` 链接不行：它指向知识库节点，系统解析不出 Base 门牌号。请表格所有者用「在多维表格中打开」拿 `/base/` 地址。
- 点「拉取数据表」，在「数据表」下拉里选表。拉不到时可以手填数据表 ID（链接里 `tbl` 开头那一段）。

**第 2 步：选视图**

- 默认「不限视图（整表拉取）」；视图只决定拉哪些行，不决定能勾哪些字段。

**第 3 步：勾字段**

- 勾选要作为下拉选项来源的字段，**至少勾一个**。

**第 4 步：核对源标识与父列，创建**

- 「源标识」会进接口地址，全局唯一，**创建后不能改**。默认按表 ID + 字段 ID 生成（如 `tblxxx_fldyyy`）；要改只能用小写字母开头、只含小写字母/数字/下划线的 1～64 字节字符串（如 `expense_type`）。
- 要做级联（父字段决定子字段范围）时，在「父列」选同表里另一个已勾选的字段；否则保持「无父列（顶级）」。多选字段不能当父列。
- 点「创建数据源」。成功后会弹回执：
  - 通了：「数据源已创建，链路是通的：服务端这次拉到了 N 个选项。」并给出可复制的数据源标识。
  - 不通：「数据源已创建，但这次预检没走通：…（错误码 …）」，可点「重新填写 Token」。数据源不会因此被删。
- 创建「定时拉取」型数据源后，系统会自动替它排一次拉取；若提示没排上，到详情页点「立即拉取」。

### 2.4 把字段接进审批控件（「凭据配置」页签）

1. 在数据源列表点刚建的那一行进入详情页，切到「凭据配置」。
2. 每个字段一块，块里有：
   - **接口地址**：形如 `{本站域名}/api/v1/feishu/approval/options/{源标识}`。这个地址必须是飞书服务器能访问的公网地址；如果你是从 localhost 或内网打开控制台，复制出的地址审批后台会校验失败，找运维要公网地址。
   - **Token**：平时显示掩码。
   - **联动 key**（只有带父列的字段才有）：父字段在多维表格里的字段 ID（如 `fldCaTg1`）。
3. 点「接口地址」旁边的「复制」，粘到审批后台该控件的「外部选项」接口地址里；点「Token」旁边的「复制」取明文（纯读操作，可以反复点，不改变任何状态；需要 `feishu.datasource.secret` 权限）；带级联的再把「联动 key」复制到审批后台联动控件的「参数代码」。
4. 审批后台控件里的 **「Key」（加密用）留空**，本项目不做 Key 加密。
5. 填完回审批后台点它自己的「校验数据」，能拉到选项才算接通。

> 「轮换」和「复制」不是一回事：复制只是读；轮换会**立刻作废旧 Token**，已经配好的控件马上失效，必须把新值粘回审批后台。轮换前先确认自己能改审批后台。

### 2.5 日常同步、体检与字段维护

详情页顶部有这些页签：

- **同步状态**：看「取数方式 / Base Token / 数据表 ID / 视图 ID / 取数字段 / 最近成功同步 / 最近尝试拉取 / 下次自动拉取 / 最近一次错误」。
  - 「下次自动拉取」是全局排程，所有数据源一样。间隔由运维在服务端配置 `feishu.pull_interval_seconds`（默认 15 分钟，允许 10 秒～24 小时），改完要重启服务。
- **体检结果**（只对多维表格来源显示；Excel 导入源没有这个页签）：「重新体检」会实时出网检查，结论分几段：
  - 「体检通过：勾选的字段在表里都还在，数据表与视图也都在。」
  - 「表里已经没有这些列了」「字段名重复」「字段类型不支持作为选项值」「多选字段不能作为级联父列」「远端新增、尚未绑定」「这次没查成（不算通过）」。
  - 字段**改名不算问题**，系统按字段 ID 自动跟上。
- **选项数据**：只读。选项只能通过拉取、推送、导入写入，控制台不能手工增删。
- **凭据配置**：见 2.4。
- **查询门户**：见 2.7。

页面右上角的按钮不在页签里：

- **立即拉取**（仅「定时拉取」型）：点完前端最多等 15 秒，超时会提示稍后刷新页面看「最近尝试拉取」。
- **维护字段**（仅「定时拉取」型）：点开是一个弹窗，里面可以：
  - 「改绑」：把绑定换到另一列，接口地址与 Token 不变，审批后台不用改。**改父级会改变该字段及整棵子树的选项 ID，历史审批单里的旧值可能失联，界面会红字提示，别顺手点。**
  - 「停用」：该控件的下拉会立刻取不到选项（`40301`），重新启用即可恢复；绑定行、源标识和 Token 都会保留。父字段停用前必须先处理子级，否则后端拒绝。
  - 「添加」：从「可新增字段」里加列，会**签发一套新凭据**（接口地址 + Token），必须回审批后台单独配一次。
- **重新导入**（文件导入型）：见 2.6。

其他：

- 单轮拉取上限：每张表每轮最多 20,000 行（40 页 × 500 行），超过整轮失败，不会截断。字段选项超过 100 个时靠分页，审批控件那边可能需要开启分页/搜索能力。
- 连续失败会发告警邮件，但是否真的发取决于运维配置 `feishu.alert_recipients`（默认为空 = 不告警）。

### 2.6 Excel 文件导入（4 步向导）

1. 「添加数据源」→ 选「文件导入」→ 填「名称」，选一批 `.xlsx` 文件（可多选），点「解析表头」。
2. 勾选要作为选项来源的列（至少一列）。
3. 核对「源标识」和「父列」（默认 `col_2` 这类，被占用会自动顺延）。
4. 点「创建并导入」。成功回执会逐文件报「读到 N 行 → M 个选项」；失败可点「重试导入」，**不会建第二个数据源**，但列、源标识、父列会冻结，要改只能删掉重建。

规则与坑：

- 只认 `.xlsx`。`.xls`、`.csv`、改名冒充的都会被拒。
- **只读第一张 sheet**；多 sheet 文件会提示「只读了第一张」。
- 表头 = 第一张 sheet 的第一个非全空行；表头重名整批拒绝；列名上限 64 字符。
- 多个文件之间表头必须完全一致；缺了已绑定的列会整批拒绝，多出的列忽略。
- 单文件 ≤ 16 MiB、合计 ≤ 17 MiB、最多 32 个文件。
- 数值列不会保留前导零，也不做日期/数值推断。**联行号这类列请在 Excel 里设为文本格式**，否则会丢前导零或变科学计数法。
- 超长文案（>255 字符）会被截断并停用该条选项，回执里报「异常 N 行」。
- 以后换数据：详情页右上「重新导入」，表头必须与已落定的列完全一致。列名改了等于换了身份，需要重新走向导。

### 2.7 对外查询门户

用途：把某个数据源的指定列，按一个「查询键」精确匹配后，在一个极简页面上展示「开放列」，适合把查询能力给外部人员。

1. 详情页「查询门户」页签 → 右上「创建门户」。
2. 填「标题」；选「查询键」（用来精确匹配的列，不会展示）；勾「开放列」；选「访问模式」：公开 / 口令 / 需登录。
3. 按需填：口令（至少 8 位）、口令有效期（天）、自定义短链（如 `bank-card`）、未找到提示、限速（1～120 次/分钟，默认 30）、是否启用模糊补全、模糊匹配最低位数（2～16，默认 4）、每个开放列的展示名映射。
4. 创建后复制链接 `{本站域名}/portal/{短链}` 发给对方。
5. 门户行内可「停用 / 启用 / 删除」，点「日志」看「时间 / IP / 查询值哈希 / 结果数 / 状态」（命中 / 未命中 / 限速 / 口令错误）。

限制：

- 查询是**精确匹配**，模糊匹配只用于输入框自动补全，不会把查询变成「包含」。
- 结果最多显示 100 条；开放列子行超过 10,000 行会截断并提示。
- 口令模式不支持自动补全（建议直接输入完整值）。
- 登录日志里查询值只存哈希，事后无法反查原始查询值。
- 门户删除后链接立即失效，访问日志保留；停用后链接同样失效，但配置保留。

### 2.8 数据源常见错误

| 错误码 / 提示 | 意思 | 找谁 / 怎么办 |
|---|---|---|
| `40902` 出站凭证未配置或仍是占位值 | 服务端没配 `feishu.app_id` / `app_secret` | 运维 |
| `40901` 未配置 `[feishu]` 段 | 服务端没开飞书集成 | 运维 |
| `1254302 Permission denied` | 应用不是这张 Base 的文档应用 / 没有权限 | Base 所有者把应用加为文档应用；高级权限给「可管理」 |
| `1254024 InvalidFieldNames` | 列名对不上 | 检查表头 / 列名 |
| `40903` 取数方式不是「定时拉取」 | 想对文件导入/手工推送源点「立即拉取」 | 按类型操作，不能互转 |
| `40102` Token 不匹配 | 审批控件里的 Token 与系统里存的不一致 | 回「凭据配置」重新复制 Token；不用重建数据源 |
| `40301` 数据源已停用 / 字段已停用 | 控件暂时取不到选项 | 重新启用该字段或数据源 |
| `50002` 服务端未配置加密密钥 | 有人在审批控件填了「Key」但服务端没配加密 | 把 Key 留空 |
| `50401` 超时 | 选项表太大或级联太深，飞书 3 秒超时 | 缩小选项范围，或找运维 |
| `40003` 联动参数有多个候选父值 | 级联判不出父值 | 检查联动参数是否只挂了一个 |
| `40004` 父值在库里不存在 | 父选项已失效 | 重新选父值或刷新数据 |
| 表头重名列 / 缺列 | Excel 表头问题 | 按 2.6 修表头后重新导入 |
| 一部分字段暂停 | 有字段被跳过，其余仍在同步 | 去「维护字段」修，不要反复点「立即拉取」 |

## 3. 飞书审批管理后台怎么用（企业审批管理员）

> 这一节主要给**企业审批管理员**。业务同事知道「审批定义是在飞书侧建的、本系统不代建」即可。

### 3.1 建一个审批定义并发布

1. 打开审批管理后台：<https://www.feishu.cn/approval/admin/approvalList?devMode=on>（需要审批管理员权限；`devMode=on` 是开发者模式，可给控件设置自定义 ID。本系统不需要自定义 ID，用普通后台链接也可以）。
2. 点右侧「创建审批」→「创建自定义审批」（也可以从模板库选模板）。
3. 「基础信息」：填名称、分组、谁可以提交该审批、流程管理员。
4. 「表单设计」：逐个添加控件。**建议控件名称与多维表格列名逐字一致**（系统默认按「去空格后完全相等」自动匹配，向导里也能手动选列）。
5. 「流程设计」：设置审批节点和审批人。**必须使用标准审批流程，不要选「自由流程」，自由流程无法用接口提单（错误码 1390013）。**
6. 点右上角「发布」。**只有已发布且在用的审批定义才能被系统提单**；已停用会报 `1390015`。

### 3.2 哪些控件能被系统自动填写

| 类别 | 控件 |
|---|---|
| **可自动映射** | 文本、多行文本、数字、金额、公式、日期、日期区间、单选、多选、人员、部门、电话、明细、附件（`attachmentV2`，自动搬运）、图片（`image` / `imageV2`，自动搬运）、关联审批（`connect`）、请假/加班/外出控件组（只映射官方白名单子控件） |
| **不展示、不映射** | 说明、引用多维表格、流水号、收款账户、出差控件组、补卡控件组、`apaascorehr*` 系列、旧控件组（请假/补卡）、换班控件组（官方支持但本系统尚未实现） |
| **需要人工准备值** | 地址、旧版附件、文档。**这些控件若是必填，保存配置会直接失败**，只能改审批定义或换定义 |

表里的英文名是内部类型名，审批后台界面上显示的是中文。拖控件时优先从「可自动映射」这一行里选；附件和图片请用当前版本的新控件，不要用旧版附件。请假/加班/外出控件组只支持官方规定的子控件，在系统「预览控件」里能看到哪些子控件可映射。

补充规则：

- 必填控件必须映射到一列，否则第 2 步「下一步」是灰的；绕过前端也会被服务端一次报全原因。
- 可选的未映射控件可以留空（官方允许不传非必填控件）。
- 「不展示、不映射」的控件如果设成必填，保存配置也会失败；请改成非必填或换控件。
- 金额控件的**币种只能从审批定义里金额控件设置的币种取**（内部名 `currencyRange`），字段映射里没有币种列。
- 附件搬运：只支持 `attachmentV2` / `image` / `imageV2`，来源必须是多维表格附件列；图片单文件 ≤ 10 MiB，其他附件 ≤ 50 MiB。
- 关联审批控件只认「实例 Code」或飞书 AppLink，不能填审批编号、审批定义 Code 或多维表格记录 ID。

### 3.3 拿到「审批定义 Code」和「数字 id」

1. 在审批列表找到刚建的定义，点编辑图标进入编辑页。
2. 看浏览器地址栏：`definitionCode=` 后面那一段就是**审批定义 Code**（形如 `E3254848-D172-4169-B03E-744E7CD11F06`）。
3. 地址栏里 `id=` 后面那串纯数字是审批定义的**数字 id**，系统只用它生成「打开审批定义」的跳转链接，不参与提单。
4. 在本系统建配置时，可以只粘 Code，也可以粘**整条编辑页地址**（系统会自动解析）。**不要粘审批列表页地址**（没有 `definitionCode`，会被当成 Code 导致报错）。

改过审批表单或流程后：审批管理员先**重新发布**；再通知业务管理员到本系统**编辑配置 → 重新预览控件 → 保存**，刷新控件结构快照，否则会报「审批定义快照与字段映射不一致」。

### 3.4 外部选项控件怎么填

开始前确认：2.2 的飞书应用已经建好、开通权限、发布，并被加为这张 Base 的文档应用；你有本系统账号，能进入「飞书数据源」并复制 Token（需要 `feishu.datasource.read` 和 `feishu.datasource.secret`）；数据源和字段已经建好并启用。缺哪一项就找对应管理员。

在表单设计里点单选/多选控件，在右侧的选项设置里选「使用外部选项」（不同版本的入口可能叫「选项来源」或「数据来源」；找不到时先确认控件类型是单选或多选）：

| 审批后台字段 | 填什么 |
|---|---|
| 请求 URL（本系统叫「接口地址」） | 本系统数据源详情页「凭据配置」里的**接口地址** |
| Token | 该字段的 **Token** |
| Key（加密用） | **留空** |
| 联动参数（本系统叫「联动 key」） | 带级联的字段填该字段的**联动 key**（形如 `fldCaTg1`）；没有级联不填 |

填完点审批后台自己的「校验数据」，能拉到选项才算接通。字段选项超过 100 个时，审批控件可能需要开启分页/搜索能力才能看全。

级联要父子两个控件都配：父控件正常配外部选项；子控件的外部选项里，把本系统复制的「联动 key」填到联动参数/参数代码，并指定它依赖父控件的哪个值。不同版本叫法不同，以审批后台界面为准。

### 3.5 应用权限、事件订阅与发布（运维 / 应用管理员）

本节由飞书应用管理员或运维执行，审批管理员通常没有开发者后台权限。你需要知道目标应用的名称或 App ID，由系统管理员提供；不知道是哪个应用就先问清楚，应用列表里可能有多个。

1. 开发者后台 <https://open.feishu.cn/app> → 应用详情 →「开发配置 → 权限管理 → API 权限」，开通第 2.2 节列出的权限（scope）。
2. 「开发配置 → 事件与回调 → 事件配置」：
   - 请求地址填 `http://47.109.148.207:18654/api/v1/feishu/event/challenge`。如果飞书后台要求 https，说明 TLS 还没配好，先找运维处理，不要自己把 http 改成 https。
   - 订阅「审批实例状态变更」（`approval_instance`），需要时再加「审批任务状态变更」（`approval_task`）。
   - 「加密策略」里生成加密密钥（Encrypt Key）和校验令牌（Verification Token），单独交给系统管理员写入服务端配置。这两个值相当于门锁和暗号，不要发群、不要填进任何页面。
   - **没配校验令牌时，系统根本不会启用事件接收。**
3. 「应用发布 → 版本管理与发布」创建版本并申请线上发布，企业管理员审核通过。**每次改权限都要重新发布。**
4. 两层订阅缺一不可：
   - 应用级：开发者后台的事件订阅 + 发布应用；
   - 审批定义级：系统会自动为每条配置订阅对应审批定义的事件，你不需要操作。
   如果发布应用或改事件配置后审批状态不再回填，找运维重启一次系统服务；系统启动时会自动重新订阅全部启用配置。
5. 怎么判断配好了：保存事件地址时飞书校验通过；发一条测试审批后，几分钟内表格的「申请状态」等列开始变化。没有变化就按上面的顺序检查，或找运维。

### 3.6 发起人身份授权（系统页顶部「飞书用户身份」卡片）

- 工作流里传 `applicant`（触发人姓名）时，系统要用**用户身份**去通讯录把姓名解析成 open_id。这就是「飞书用户身份」授权的作用。
- 这是**系统级单账号授权**：由系统管理员或业务管理员（需要能打开「审批派发」页，通常要 `feishu.approval.read` 或以上）在系统「审批派发」页顶部点「去授权」（已授权时按钮是「重新授权」），在飞书完成授权后回到页面看到「已授权：<姓名>」。建议用固定的管理员飞书账号授权，并在人员交接时重新授权。
- 授权满 350 天页面开始提醒，**365 天内必须重新授权**。
- 授权前，飞书应用管理员或运维要确认三件事（审批管理员通常没有开发者后台权限，不需要自己去做）：
  1. 开发者后台「安全设置 → 重定向 URL」里加了与 `feishu.oauth_redirect_uri` **逐字一致**的回调地址（当前是 `http://47.109.148.207:18654/api/v1/feishu/oauth/callback`）；
  2. 开通 `contact:user:search`、`contact:contact.base:readonly`、`offline_access`；
  3. 「安全设置 → 刷新 user_access_token」开关已开启。
- 授权页报 `20027` 或接口报 `99991679`，通常是 scope 不全；报 `20074` 通常是刷新开关没开。

### 3.7 审批后台常见错误

| 错误码 / 提示 | 意思 | 怎么办 |
|---|---|---|
| `1390015` | 审批定义已停用 | 回审批后台启用该定义后重试 |
| `1390002` | 审批定义 Code 不对 | 从编辑页地址栏重新复制 |
| `1390013` | 自由流程不支持 API 提单 | 改用标准审批流程 |
| `99991672` | 应用缺审批/通讯录 scope | 开通并重新发布应用 |
| 「approval_code 含非法字符：https://…」 | 粘了不带 `definitionCode` 的地址 | 粘编辑页地址或裸 Code |
| 「审批定义快照与字段映射不一致」 | 审批定义改过控件但系统没刷新 | 编辑配置 → 重新预览控件 → 保存 |
| 「必填控件「X」没有配置有效的多维表格列」 | 控件名与列名对不上，或必填未映射 | 向导第 2 步手动选列，或改名称 |
| 「单选/多选的选项无法从列里派生」 | 选项文案与表格选项不一致 | 两边文案逐字一致，或改用外部选项并选来源 |
| 「控件「X」需要人工准备值」 | 地址/旧附件/文档等不支持自动派发 | 改控件类型或去掉必填 |

## 4. 配置审批派发：让表格里的记录变成审批单（业务管理员）

### 4.1 一条「审批派发配置」是什么

- 等于：**一张多维表格的某张数据表 + 一个飞书审批定义**。
- 同一张数据表只能有一条配置（同一张表的不同视图仍算同一张表）；不同数据表可以共用同一个审批定义，各建各的配置。
- 本系统负责「配置 + 派发 + 回填 + 记录」；飞书多维表格负责「按钮触发」；飞书审批后台负责「审批定义本身」。
- **系统不会自动发现新记录。点击按钮是审批派发的唯一入口。**
- 新建配置需要同时持有 `feishu.approval.write` 和 `feishu.datasource.write`（或为系统管理员）。

### 4.2 新建配置（4 步向导）

进入「审批派发」→「配置」页签 → 右上「新建配置」。

**开工前，先在多维表格里建好这些列**（向导只能从已有列里选，缺列时下拉为空、无法继续）：

- 申请人（人员类型，必须；除非你打算让工作流传 applicant 姓名）。
- 审批编号（文本或超链接，必须）。只想看编号用文本列；想点开审批单用超链接列，但超链接列的失败原因不会写进格子。
- 按需：申请状态、审批流程、发起时间、完成时间、发起人部门、当前处理人。
- 如果要用页面按钮批量提交，必须再建一个复选框列，例如「批量提交」。

**第 1 步：选来源数据表**

- 「多维表格 Base Token」：粘贴 Base 链接或 Base Token，点「拉取数据表」。
- 「数据表」：选目标表。拉不到时手填「数据表 ID」（链接里 `tbl` 段）。

**第 2 步：预览审批控件并建立对应关系**

- 「审批定义 Code」：粘贴 Code 或审批后台地址，点「预览控件」。可切换「显示技术信息 / 隐藏技术信息」查看控件 ID 与类型。
- 「审批控件 / 对应多维表格字段」表里逐行选列：
  - 必填控件显示「必填」，必须选一列；可选控件可选「不映射」。
  - 明细分组、控件组父级只展示分组，子控件分别选列。
  - 使用本系统外部选项的控件，还要选「外部选项来源」（先选数据源，再选字段）。来源失效或停用会阻止下一步。

**第 3 步：指定申请人、回填列与批量范围**

| 界面字段 | 填什么 | 类型要求 |
|---|---|---|
| 申请人员字段 | 审批单的申请人列 | 必须是人员列（除非每行都由工作流传 applicant 姓名）；这一列也是系统回写申请人 open_id 的地方。open_id 是飞书账号的唯一编号，系统自动处理，你不用自己填。 |
| 回填字段 | 审批编号写回的列 | 文本、超链接、单选、日期、人员。只想看编号用文本列；想点开审批单用超链接列，但超链接列失败时格子不会写原因。 |
| 批量范围复选框列（页面按钮必填） | 只有勾选且回填列为空的记录才参与批量提交 | 必须选「复选框」列（type=7 是内部编号，不用管）。**只要打算用页面按钮，就必须建这一列并在这里选上；留空时点一次页面按钮会提交整张表所有回填列为空的行。** |
| 申请状态回填列（可选） | 审批中 / 已通过 / 已拒绝 / 已取消 / 已删除 | 文本或单选 |
| 审批流程回填列（可选） | 已到达节点的「节点名✓/✗/⏳」 | 文本或单选；单选列会随流程自动新增选项 |
| 发起时间回填列（可选） | 审批开始时间 | 日期 |
| 完成时间回填列（可选） | 审批结束时间；未完成不写 | 日期 |
| 发起人部门回填列（可选） | 发起人部门名（解析失败写部门 ID） | 文本 |
| 当前处理人回填列（可选） | 当前待处理人；终态清空 | 人员 |
| Base 时区 | 日期换算时区 | 默认北京时间（`Asia/Shanghai`），一般不用改；配错会让审批里的时间整体偏移 |

**第 4 步：核对并创建**

核对摘要后点「创建配置」。校验失败会一次报全原因，按提示回上一步改。**新建配置默认已启用。**

创建后可以点列表里的「补充名称」/「补充本页名称」刷新多维表名、数据表名、审批名、列名快照。名称只用于展示和搜索，不影响派发；名称缺失不代表配置失效。

### 4.3 「接入数据」页：拿派发链接与模板

进入配置详情 →「接入数据」页签：

| 项目 | 说明 |
|---|---|
| 派发链接 | 形如 `http://47.109.148.207:18654/api/v1/feishu/approval/dispatch/<配置标识>`。**以「接入数据」页复制出来的为准**，不要手动把 http 改成 https；必须是飞书服务器能访问的公网地址，localhost/内网地址不行 |
| 访问 Token | 每条配置独立一份，放在请求体的 `token` 字段。它和数据源「凭据配置」里的 Token 不是同一个，别混。「复制 Token」是纯读，可反复点；「轮换访问 Token」会签发新值并**立刻作废旧值** |
| 单行模板 | 带 `record_id`，给行内按钮用 |
| 批量模板 | 不带 `record_id`，给页面批量按钮用 |

单行模板：

```json
{
  "token": "<访问 Token>",
  "record_id": "<触发记录 ID>",
  "applicant": "<发起人姓名>",
  "requested_by": "<触发人标识>"
}
```

批量模板：

```json
{
  "token": "<访问 Token>",
  "applicant": "<发起人姓名>",
  "requested_by": "<触发人标识>"
}
```

> 模板里的 `<访问 Token>` 要替换成刚复制的访问 Token，它是固定字符串，不用工作流变量。

请求体字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `token` | 是 | 该配置的访问 Token |
| `record_id` | 单行必填、批量必须省略 | 行内按钮传当前记录 ID；页面批量按钮整个不要这个字段（传空串会被拒） |
| `applicant` | 否 | 发起人**姓名**（不是 open_id、不是对象）。传了会解析并回写申请人员列；不传则读表格原值 |
| `requested_by` | 否 | 只用于「派发记录」里展示请求人，不影响审批、不决定通知接收人；缺省记为 `feishu-workflow` |
| `notification_recipient` | 否 | 显式指定通知接收人对象，如 `{"receive_id_type":"open_id","receive_id":"ou_..."}`。控制台模板默认不带 |

> **旧模板已作废**：网上或旧设计文档里带 `Authorization: Bearer`、`base_token`、`table_id`、`approval_code` 的模板是改版前的契约。现在请求体里多写模板以外的字段会被直接拒绝。**一律以控制台「接入数据」页复制的模板为准。**

### 4.4 启用、停用、编辑、删除

- **启用**只表示这条配置允许受理新的派发请求，**仍需飞书工作流触发**。它不代表工作流已接通、权限正确或审批能成功运行。
- **停用**后新的派发请求不再通过此配置受理，但不会取消已创建的审批、不撤回在途任务。
- **编辑**只能改：配置名称、Base 时区、字段对应、六个扩展回填列、批量范围复选框列、审批定义链接（用于「打开审批定义」跳转）。**来源 Base、数据表、审批定义 Code、申请人列、编号回填列建好后不可改**，要换只能删除重建。
- **删除**会清掉配置、字段映射和该配置全部任务行（含已完结），仅派发请求记录保留，**不可恢复**。如果配置下还有「待处理 / 创建中 / 已创建 / 待人工核查」的任务，系统会拒绝删除（提示先完成或核查），防止丢失恢复证据。
- **删除前**：先停用或删除飞书多维表格里对应的按钮和自动化，确认不会再有人点；否则配置删掉后，旧派发链接会返回 `40401`「该派发链接未配置审批派发」。

### 4.5 派发记录与任务状态

「派发记录」页一次请求一行，结果分四类：

| 结果 | 含义 | 你该做什么 |
|---|---|---|
| 成功（succeeded） | 单条请求已创建审批并回填编号 | 看表格编号即可 |
| 等待（waiting） | 本轮没创建审批，通常是必填数据缺失或格式不对；系统不写任何表格字段 | 补齐数据后再点；重复点不会建重复单 |
| 已受理（accepted） | 批量请求已入队，不代表每条都成功 | 展开该行「查看任务」逐条看 |
| 失败（failed） | 请求失败；**也可能是可重试失败**（如飞书暂时不可用/频控），任务仍在后台重试并可能成功 | 先看结果行的「说明/消息」和回填列文字，不要急着重复点 |

任务状态（在「已受理」的批量行展开后点「查看任务」）：

| 状态 | 中文 | 含义 |
|---|---|---|
| `pending` | 待处理 | 等数据补齐，或可重试 |
| `creating` | 创建中 | 早期过渡状态，现在很少出现 |
| `created` | 已创建 | 早期过渡状态，现在很少出现 |
| `backfilled` | 已回填 | 编号已写回，处理完成 |
| `terminal` | 终止 | 结构性问题，通常需要人工改配置或清空回填列后重试 |
| `unnotified` | 未通知 | 处理结束，但通知没送达（接收人缺失或发送失败）；不会自动重试通知 |
| `review` | 待人工核查 | 外部写入结果未知（例如创建响应丢失），系统禁止自动重放，需要先去飞书核对 |

说明：

- 「派发记录」的任务下钻只对「已受理」的批量行开放，且只显示该配置最近 20 条任务；单条请求行展开只有一串给技术同事看的原始内容（请求/返回 JSON），不是给业务看的原因说明。单条失败时以结果行的「说明/消息」和回填列文字为准；需要看任务明细就找业务管理员。
- 从配置详情点「查看派发记录」不会自动按该配置过滤，需要自己按 Base Token / table_id 筛。
- 失败原因通常也会写进回填列（文本列会写；超链接列失败时格子保持空白，原因只在任务/记录里）。**清空回填格是人工重试的通道**：清空后下一次点击/批量扫描会重新处理这一行。

### 4.6 什么情况下会收到飞书消息

- 通知接收人顺序：请求里显式指定 → 解析出的申请人 → 记录创建人。三者都没有，就没人收到，任务落「未通知」。
- `requested_by` **不是**通知接收人，只用于日志展示。
- 单条成功/失败会发；批量受理后，后台**逐条**处理并逐条发结论，一次批量可能收到很多条消息。
- 中间状态只有「本轮原因与上一轮不同」才发，不会每 30 秒重复轰炸。
- 批量点击但一条都没命中时，会给点击人发一条标题为「【批量提交未处理任何记录】」的消息，说明原因和下一步。

### 4.7 重试与防重复

- **等待**：补齐申请人/必填字段后再点一次即可。
- **终止**：先按原因修配置或数据，再**清空回填列**，然后重新点按钮。
- **待人工核查**：系统不会自动重放，点按钮也会提示先核对。请到飞书确认这张单是否已创建，再决定怎么处理。
- **已成功建单的记录不要为了「重试」去清空回填列**。系统给每条记录记了一个固定编号，重复点击不会建出第二张审批单，但会白白多跑一轮处理。
- 只有从未创建成功的行，才靠清空回填列重试。

### 4.8 派发失败原因速查

| 提示 | 意思 | 怎么办 |
|---|---|---|
| 「申请人字段「X」缺少有效人员 ID」 | 申请人员列为空或类型不对 | 补齐人员列 |
| 「发起人姓名解析失败：未找到「X」」 | 工作流传的姓名在通讯录里查不到 | 检查工作流变量，或改用唯一姓名 |
| 「存在多个同名「X」」 | 通讯录重名 | 改用唯一姓名，或改由表格人员列提供申请人 |
| 「飞书用户身份未授权」 | 没做 OAuth 授权 | 页面顶部「去授权」 |
| 「访问 Token 无效」 | 轮换过 Token 但工作流还是旧值 | 回「接入数据」复制新 Token 更新工作流 |
| 「该审批派发配置已停用」 | 配置被停用 | 启用配置 |
| 「该派发链接未配置审批派发」 | 配置标识错 / 配置被删 | 核对派发链接 |
| 「该配置尚未签发访问 Token」 | 还没签发过凭据 | 点「轮换访问 Token」 |
| 「审批定义已停用」 | 飞书侧定义未发布/停用 | 审批后台启用并重发布 |
| 「审批定义快照与字段映射不一致」 | 定义改过控件 | 编辑配置，重新预览控件并保存 |
| 「所选文案没有审批选项映射」 | 单选/多选选项文案对不上 | 两边文案逐字一致，或改用外部选项 |
| 「没有匹配的启用选项」 | 已选外部选项来源，但选项停用/文案不一致 | 检查数据源选项与控件配置 |
| 「审批派发 Worker 未在运行」 | 系统的后台处理程序没在运行 | 找运维重启，不需要你处理 |
| 回填列类型不支持 | 回填列不是文本/链接/单选/日期/人员 | 换列或改列类型 |

## 5. 在飞书多维表格配置批量提交工作流（表格所有者 / 业务管理员）

### 5.1 原理先讲清楚

本系统**没有内置的「批量提交」按钮**。你在系统表格里勾选行看到的是通用表格批量操作，**不会触发审批派发**。真正的批量提交，是在飞书多维表格里建一个「自动化（工作流）」：

```
同事点按钮  →  飞书自动化「发送 HTTP 请求」  →  本系统派发接口  →  创建审批单  →  编号/状态回填表格
```

两种按钮，用途不同：

| 按钮类型 | 在哪里加 | 能拿到什么 | 一次处理 |
|---|---|---|---|
| **行内按钮**（`buttonField`） | 数据表里的「按钮」字段 | 当前记录的 `recordId` + 触发人 + 所有字段值 | 一条记录，同步返回结果 |
| **页面按钮**（`buttonElement`） | 仪表盘 / 应用页面上的「按钮」组件 | 只有触发人、按钮名、时间，**没有记录** | 一整轮队列（按筛选条件扫描），只返回「已受理」 |

> **不要用定时触发**：多维表格自动化的运行次数是企业级共享额度，超限后会静默停摆到次月 1 日。本方案只使用「按钮点击」触发。

### 5.2 方式一：行内按钮（逐条提交，推荐先做这个）

前置：第 4 章的审批派发配置已建好，且页面顶部「飞书用户身份」显示「已授权」。你需要能进入这条配置的「接入数据」页；没有权限就让业务管理员把派发链接、访问 Token 和两份模板发给你。

1. 进入配置详情 →「接入数据」，复制「派发链接」；点「复制 Token」拿到访问 Token；点「复制单行模板」。
2. 打开目标多维表格，给数据表新增一个字段，类型选「按钮」。
3. 点表格右上角「自动化」（部分版本叫「工作流」）→ 新建自动化。
4. 触发器选「按钮点击时」，选择刚加的按钮字段。
5. 添加一个动作「发送 HTTP 请求」：
   - 请求方法：`POST`
   - 请求地址：粘贴「派发链接」
   - 请求头：加一行 `Content-Type`，值 `application/json`。**不需要 Authorization。**
   - 请求体：选 raw / JSON，粘贴「单行模板」。
6. **先替换访问 Token**：把模板里的 `<访问 Token>` 换成第 1 步复制的访问 Token。它是一串固定字符，直接粘进去，不用变量。
7. **再把其余占位符换成工作流变量**：
   - `record_id`：换成触发器的「记录 ID」变量。做法是删掉尖括号里的占位文字，光标留在双引号里面，点「插入变量」，选触发节点下的「记录 ID」。工作流里可能显示成 `$.step_btn.recordId`，不要自己手打这串代码。
   - `applicant` 和 `requested_by`：换成触发器的「触发人」变量。同样用「插入变量」选，显示什么以界面为准；它渲染出的是**姓名文本**，两个字段都要字符串，**不要传对象**。
   - **重要**：如果表格的申请人员列已经填好了每行真正的申请人，请把 `applicant` 这一行整个删掉，让系统读表格。只有「点按钮的人就是申请人」时，才用触发人变量。否则审批会建在点按钮的人名下，并覆盖该行原来的申请人。
   - 常见错法：占位文字没删干净、变量插到引号外面、手打了半截代码。改完检查一下请求体还是不是合法的 JSON。
8. 响应类型选 JSON，响应示例填 `{}`（只是让工作流能解析返回，不影响业务）。
9. 保存并启用自动化，在自动化列表里确认它显示「已启用」。
10. **单条验证**：在表里填一条测试记录的全部必填内容，点这一行的按钮。
11. 几秒后：表格「审批编号」列出现编号；到系统「派发记录」页看到一条「成功」。回填列是文本列时看到编号即可；是超链接列时再点开验证能打开审批单。

### 5.3 方式二：页面按钮（批量提交）

前置：在表里新增一个**复选框**列，例如叫「批量提交」；并在系统配置第 3 步把它设为「批量范围复选框列」。

1. 在仪表盘或应用页面添加一个「按钮」组件。路径通常是：多维表格顶部「仪表盘」→ 新建仪表盘 → 添加组件 → 按钮；或在「应用模式」的页面里加按钮。找不到入口就找表格所有者一起做。
2. 新建自动化，触发器选「页面按钮点击」（`buttonElement`），并选中刚加的那个按钮组件。
3. 添加「发送 HTTP 请求」：方法、地址、请求头同 5.2。
4. 请求体用系统「复制批量模板」，**不要带 `record_id`**；先把 `<访问 Token>` 换成第 1 步复制的访问 Token。
5. `applicant` / `requested_by` 仍可引用 `$.step_btn.user`。注意：**批量请求里的 `applicant` 会写给这一轮处理的所有记录**；如果每行申请人不同，请把 `applicant` 整个删掉，让系统读表格里的申请人员列。
6. 保存并启用，在自动化列表里确认它显示「已启用」。
7. 使用：在要提交的记录上勾选「批量提交」复选框 → 点页面按钮 → 响应「已受理」。
8. 到系统「派发记录」看到「已受理」行，展开点「查看任务」，逐条核对「待处理 / 已回填 / 终止 / 待人工核查」。
9. 一条都没勾选就点按钮时，会收到「【批量提交未处理任何记录】」消息，按提示勾选后重试。

**重要提醒**：页面按钮的请求省略 `record_id` 后，会唤醒**所有启用配置**的待处理队列，不只是当前这张表。系统的提示原文是「省略 record_id 会唤醒所有启用配置的待处理队列，并非只处理请求中指定的数据表」。所以页面按钮只在确实要处理整个队列时使用。

### 5.4 可照抄的 HTTP 节点配置

```
POST http://47.109.148.207:18654/api/v1/feishu/approval/dispatch/<配置标识>
Content-Type: application/json
```

> 地址以控制台「接入数据」里复制的派发链接为准；当前环境是 http，不要手动改成 https。

单行请求体（`<访问 Token>` 换成实际 Token，其余占位符换成工作流变量）：

```json
{
  "token": "<访问 Token>",
  "record_id": "<触发记录 ID>",
  "applicant": "<发起人姓名>",
  "requested_by": "<触发人标识>"
}
```

批量请求体（没有 `record_id`；`<访问 Token>` 同样换成实际 Token）：

```json
{
  "token": "<访问 Token>",
  "applicant": "<发起人姓名>",
  "requested_by": "<触发人标识>"
}
```

变量对照：

| 变量 | 含义 | 哪些按钮有 |
|---|---|---|
| `$.step_btn.recordId` | 当前记录 ID | 仅行内按钮 |
| `$.step_btn.user` | 触发人，真机渲染为姓名 | 行内、页面按钮都有 |
| `$.step_btn.buttonName` | 按钮名 | 都有 |
| `$.step_btn.time` | 触发时间 | 都有 |

> 这些是工作流变量的技术写法，不要手打；一律用工作流界面的「插入变量」选择，界面上显示什么就以什么为准。

成功响应示例（业务成功时）：

```json
{
  "code": 0,
  "message": "【审批实例已确认，编号已回填】…",
  "data": {
    "accepted": true,
    "status": "succeeded",
    "serial_number": "202609280098"
  }
}
```

失败响应（**飞书工作流仍可能显示成功，因为 HTTP 状态还是 200，只是 `code` 非 0**）：

```json
{"code": 40301, "message": "访问 Token 无效，请在控制台重新签发后更新工作流"}
```

常见业务错误码：

| code | 含义 |
|---|---|
| `40401` | 该派发链接未配置审批派发，请先在控制台创建配置 |
| `40402` | 该配置尚未签发访问 Token |
| `40301` | 访问 Token 无效（轮换过但工作流没更新） |
| `40302` | 该审批派发配置已停用 |

### 5.5 怎么确认配对

按顺序核对，任何一步不过就停下来修：

1. 表里点单条按钮 → 「审批编号」列出现编号。
2. 系统「派发记录」出现「成功」行，展开能看到审批单编号。
3. 打开飞书「审批」→「我发起的」能看到这张单，申请人、字段值正确。
4. 配了扩展回填列的话，几秒到几十秒内「申请状态」「当前处理人」等列开始变化（依赖事件订阅）。
5. 再做批量：勾选 1～2 条 → 点页面按钮 → 「已受理」→ 展开看任务逐条「已回填」。

> **不要只看飞书工作流的执行历史判断成败。** 业务失败时飞书也可能显示「成功」，以系统「派发记录」页为准。

### 5.6 限制与坑（务必知道）

- **「已受理」不等于审批已创建**。批量请求只代表入队；逐条结果看任务状态。
- **业务失败时飞书也可能显示「成功」**，见 5.5。
- HTTP 节点响应上限 60 秒。节点超时代表「结果未知」，先查表格和派发记录，再决定是否重试（系统给每条记录记了固定编号，重复点不会建重复单）。
- 飞书工作流**不支持内网 URL**。派发链接必须是公网地址。
- 轮换访问 Token 后旧值立即失效，必须同步更新工作流。
- 一张多维表格的数据表只能建一条配置；来源 Base、数据表、审批定义、申请人列、回填列建好后不可改。
- 批量扫描每轮最多 10,000 行（20 页 × 500 行），超过会让这一轮扫描没法开始，不会只处理一部分。
- 批量处理是后台逐条跑的，飞书创建审批有约 90 次/分钟的限速，大表要等；不要因为暂时没看到编号就反复点按钮。
- 勾选范围列只在「受理/扫描」时生效；取消勾选不会撤回已经入队的任务。
- 回填列是「超链接」类型时，失败原因只写进任务/派发记录，表格格子保持空白；想直接看到失败原因，用文本列做回填列。
- 批量逐条处理会逐条发飞书消息，大表批量前先和同事打招呼。
- 系统不能撤回已经创建的审批单；要撤回只能在飞书里逐单处理。

## 6. 常见问题 FAQ（所有同事）

**Q1：我登录了，为什么左边只有「账号设置」？**
新账号默认零权限。找系统管理员按 1.4 授权对应权限，然后刷新页面或重新登录。

**Q2：管理员说已经授权了，我还是看不到菜单？**
让对方确认授权成功提示「已授予，对方刷新会话后生效」，然后你**刷新页面或退出重新登录**。仍不行就让对方检查是否给的是 `feishu.datasource.read` / `feishu.approval.read` 这类「入口权限」。

**Q3：点登录提示「密码无效」怎么办？**
核对帐号拼写；忘记密码找管理员「签发重置凭证」（1.5）。

**Q4：审批下拉框里没有选项？**
普通同事能做的：截图下拉框，记下是哪个审批、哪个字段，发给业务管理员。
业务管理员按顺序查：数据源是否存在且启用 → 字段绑定是否启用 → 数据源「体检结果」是否通过 → 审批控件的地址/Token 是否与「凭据配置」一致 → 选项是否已经同步（点「立即拉取」后稍等）。错误码对照见 2.8。

**Q5：点按钮没反应 / 没出现审批编号？**
先确认按钮确实被点了：系统不会自动发现新记录，必须有人点。如果你看不到「审批派发」菜单，说明没有 `feishu.approval.read`：把表格名称、这一行内容、审批编号（如果有）、点击时间发给业务管理员代查，或按 1.4 申请只读权限。能看到「派发记录」时：没有记录 = 请求没到系统；有「等待」= 数据不全；有「失败」= 按 4.8 对原因。不要只看飞书工作流历史。

**Q6：会不会重复建审批单？**
不会。系统给每条记录记了一个固定编号，同一条记录重复点击不会建第二张单。但清空回填列后重试、或换了审批定义重建配置，可能被当成新记录再建一单。

**Q7：批量提交为什么把别的表也处理了？**
页面按钮省略 `record_id` 后会唤醒所有启用配置的待处理队列。这是设计行为，见 5.3。

**Q8：批量之后有些行没编号？**
逐条看任务状态：等待/终止/待人工核查分别按 4.5、4.7 处理。失败原因可能写在回填列（文本列）里，超链接列不写。

**Q9：表格里改了列名、加了列怎么办？**
改已有列的**列名**：多维表格源的绑定按字段 ID 走，改名不影响；但 Excel 导入源的列名就是身份，需要重新走向导。加列：数据源里用「维护字段 → 添加」新增（会签发新凭据，要回审批后台单独配）；审批配置的映射需要编辑配置重新预览并保存。

**Q10：能撤回已经发起的审批吗？**
本系统不能。请到飞书里逐单处理。

**Q11：能换审批定义 / 换来源表吗？**
不能。配置建好后这几项固定，只能删除重建（删除前确认没有在途任务）。

**Q12：审批状态/完成时间一直不更新？**
先确认配置第 3 步填了对应的「申请状态回填列」「完成时间回填列」，且列类型正确；再确认飞书事件订阅仍然有效（按定义订阅可能在应用发布后丢失），找运维重启系统服务；最后看是否有「未通知/待人工核查」任务。

**Q13：收到「【批量提交未处理任何记录】」？**
说明没有符合「已勾选 + 回填列为空」的记录。按消息提示勾选后重试；全部都有编号时，如需重提先清空对应回填格。

**Q14：Excel 导入后数字少了前导零 / 变了科学计数法？**
源文件把该列存成了数值。请在 Excel 里把列设为文本格式，重新导入。

**Q15：页面上的「复制」点了没反应？**
用 http 打开页面时，浏览器可能禁止网页自动复制。手动全选复制；系统通常会把完整内容摊开显示。

**Q16：普通同事提交审批需要本系统的权限吗？**
不需要。只要你能打开飞书多维表格、能编辑这一行、能看到并点击提交按钮即可，不用开通本系统的后台权限。不要为了提交审批去申请 `feishu.approval.write` 这类管理员等价权限。看不到按钮或表格是只读的，找表格所有者。

## 7. 出问题找谁、报障带什么（所有同事）

| 问题 | 找谁 |
|---|---|
| 登录、权限、看不到菜单、重置密码 | 系统管理员（通常是首个注册的账号） |
| 服务端配置、App ID/Secret、拉取一直失败、导入/门户异常 | 运维 / 部署方 |
| 多维表格权限、添加文档应用、高级权限、字段被删 | Base 所有者 |
| 审批定义、表单/流程、审批后台权限 | 企业审批管理员 |
| 飞书应用 scope、发布、事件订阅、OAuth 授权 | 飞书应用管理员 / 运维 |
| 审批派发配置、派发记录、回填异常 | 业务管理员（持 `feishu.approval.write`） |

报障时请带上：

1. 页面路径 + 你做了什么 + 发生时间。
2. 数据源问题：数据源名称/编号、页面上的错误码、页面上那串请求编号（request_id）、「最近一次错误」原文、体检结论。
3. 派发问题：配置名称、Base Token / table_id、record_id、派发记录结果、任务「最近错误」、审批单号（如果已生成）。
4. **不要把 Token、App Secret 发在群里。** 怀疑泄露先让管理员轮换。

### A.2 服务端配置项（`[feishu]`）

| 配置 | 作用 | 默认 / 范围 |
|---|---|---|
| `enabled` | 是否启用飞书集成 | — |
| `app_id` / `app_secret` | 飞书自建应用凭据 | 必填 |
| `event_verification_token` | 事件校验 Token；不配则不注册事件端点 | — |
| `event_encrypt_key` | 事件解密 Key；配了则拒绝明文事件 | — |
| `pull_interval_seconds` | 数据源定时拉取间隔 | 900，允许 10～86400 |
| `approval_scan_interval_seconds` | 审批派发后台轮询间隔 | 30，允许 5～600 |
| `alert_recipients` | 连续失败告警收件人 | 空 = 不告警 |
| `alert_failure_threshold` | 连续失败告警阈值 | 3，允许 2～1000 |
| `oauth_redirect_uri` | 用户授权回调，必须与飞书后台逐字一致 | — |

### A.3 事件订阅检查清单

1. 开发者后台「事件与回调」请求地址：`http://47.109.148.207:18654/api/v1/feishu/event/challenge`；如果飞书要求 https，先让运维配好 TLS。
2. 订阅 `approval_instance`（可选 `approval_task`）。
3. Verification Token / Encrypt Key 已写入服务端配置。
4. 应用已发布，且 scope 变更后重新发布。
5. 每个审批定义已按 Code 订阅：系统建配置时会自动订阅；服务重启时会为全部启用配置重新订阅。
6. 状态不回流时：重启系统服务 → 检查订阅 → 检查 scope。

### A.4 安全提醒

- 当前环境是**明文 http**，登录凭据、会话 Cookie 在公网不加密传输；上线真实用户前应配 TLS 反代。
- `config_key` 与访问 Token 都是 32 字节随机数的 64 位十六进制；Token 泄露等于别人可以替你发审批。
- 审批定义 Code 是敏感标识：拿到它可读取该定义下所有数据并订阅事件，妥善保管。
- 数据源 Token 系统只存摘要 + 密文；「复制」可重复回显，但轮换不可逆。

| 审批定义 / definitionCode | 审批模板及其编码 |
| 审批实例 / instance_code | 一次提交产生的审批单 |
| 审批编号 / serial_number | 给人看的单号 |
| 外部选项 | 审批下拉框的选项从系统数据源实时拉取 |
| 派发配置 / config_key | 本系统里「哪张表 → 哪个审批」的一条配置 |
| 数据源 Token | 填进飞书审批控件「外部选项」的凭据，在数据源「凭据配置」里复制 |
| 访问 Token | 飞书工作流调用派发接口的凭据，在审批配置「接入数据」里复制 |
| 回填列 | 系统把审批编号/状态写回的表格列 |
| 批量范围复选框列 | 勾了才参与批量提交的复选框列 |
| 行内按钮 / buttonField | 数据表里的按钮字段，逐条提交 |
| 页面按钮 / buttonElement | 仪表盘/应用页面上的按钮，批量提交 |
| 自动化 / 工作流 | 多维表格里的「按钮点击 → 执行动作」 |
