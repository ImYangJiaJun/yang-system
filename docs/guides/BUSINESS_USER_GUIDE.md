# YANG System 审批派发配置指引

> **适用对象**：负责配置审批派发的业务人员。系统已部署，飞书自建应用与基础配置已由管理员配好。
> **系统地址**：`http://47.109.148.207:18654`（必须带端口，目前只能用 http）
> **本文只讲配置流程。**

---

## 0. 配置流程总览

| 步骤 | 在哪里做 | 产出 |
|---|---|---|
| 1. 配置外部数据源 | 本系统 + 飞书审批后台 | 每个下拉字段的接口地址和 Token |
| 2. 修改飞书审批定义 | 飞书审批管理后台 | 已发布的审批定义 + 审批定义 Code |
| 3. 配置提交用的多维表格 | 飞书多维表格 | 一张带三个字段、且已加入「审批自动化」文档应用的表 |
| 4. 在本系统配置审批派发 | 本系统 | 派发链接 + 访问 Token + 请求体模板 |
| 5. 建按钮/自动化并测试 | 飞书多维表格 + 本系统 | 能正常建单、回填、查记录 |

开始前确认三件事：

- 系统「审批派发」页顶部的「飞书用户身份」显示「已授权」；没有就找系统管理员。
- 你有一个已发布的飞书审批定义；没有就先按第 2 章建一个。
- 数据源是多维表格、或要建提交表时，都要把自建应用「审批自动化」加为这张 Base 的文档应用，并授予「管理」权限。步骤见第 1 章开头和第 3 章第 10 步。

## 1. 配置外部数据源

**什么时候需要这一章**：审批表单里的单选/多选下拉，如果选项要来自多维表格或 Excel，就在这里建数据源，拿到「接口地址 + Token」填进审批控件。没有这种下拉就跳过。

> **前置：把「审批自动化」加为文档应用。** 如果数据源是多维表格，先打开这张 Base，点右上角「…」→「更多」→「添加文档应用」，搜索「审批自动化」，添加，并把权限设为「管理」（也可能显示为「可管理」）。没加这一步，后面「拉取数据表」「立即拉取」会报 `1254302 Permission denied`，或者调用成功但返回空数据。数据源是 Excel 导入时不需要这一步。

### 1.1 从多维表格建数据源

1. 左侧「飞书数据源」→ 右上「添加数据源」→ 选「多维表格」。
2. 第 1 步：填「名称」；在「Base Token」粘贴多维表格的 `/base/` 链接。知识库 `/wiki/` 链接不行，请用「在多维表格中打开」拿 `/base/` 地址。点「拉取数据表」，选「数据表」。
3. 第 2 步：选「视图」。默认「不限视图（整表拉取）」。
4. 第 3 步：勾选要作为下拉选项的字段，至少勾一个。
5. 第 4 步：核对「源标识」和「父列」。源标识会进接口地址，创建后不能改；要做级联就选父列，否则保持「无父列」。
6. 点「创建数据源」。成功回执会写「链路是通的」，并给出数据源标识；不通时按 1.4 处理。
7. 建好后系统会自动拉取一次；没排上就到详情页点「立即拉取」。

### 1.2 把接口地址和 Token 填进审批控件

1. 进入数据源详情 →「凭据配置」。每个字段一块：
   - **接口地址**：`{系统地址}/api/v1/feishu/approval/options/{源标识}`。
   - **Token**：平时显示掩码，点「复制」取明文，可以反复复制。
   - **联动 key**：只有带父列的字段才有。
2. 去飞书审批后台，在该单选/多选控件的外部选项里填：请求 URL 填接口地址，Token 填该字段 Token；「Key」留空；有级联的把「联动 key」填到联动参数/参数代码。
3. 点审批后台的「校验数据」，能拉到选项才算接通。
4. 「轮换」会立刻作废旧 Token，已经配好的控件马上失效；轮换后必须把新 Token 粘回审批后台。

### 1.3 Excel 导入（数据不在多维表格时）

1. 「添加数据源」→「文件导入」→ 填名称，选一批 `.xlsx`，点「解析表头」。
2. 勾选要作为选项的列，至少一列。
3. 核对源标识和父列，点「创建并导入」。
4. 只认 `.xlsx`，只读第一张 sheet；表头必须一致且不能重名；单文件 ≤16 MiB、合计 ≤17 MiB、最多 32 个。
5. 以后换数据点「重新导入」，表头必须与已落定的列一致。

### 1.4 建好后的检查与常见错误

在数据源详情页看：

- **同步状态**：最近成功同步、下次自动拉取、最近一次错误。
- **体检结果**（仅多维表格源）：字段、数据表、视图是否还在。
- 右上角 **维护字段**：改绑、停用、新增字段。改父级会影响历史选项 ID，界面有红字提示，别顺手点。

| 现象 | 意思 | 怎么办 |
|---|---|---|
| `40102` Token 不匹配 | 审批控件里的 Token 和系统不一致 | 回「凭据配置」重新复制 Token |
| `40301` 数据源或字段已停用 | 控件取不到选项 | 重新启用字段 |
| `50002` 服务端未配置加密密钥 | 审批控件里填了「Key」 | 把 Key 留空 |
| `50401` 超时 | 选项太多或级联太深 | 缩小选项范围，或找运维 |
| `1254302 Permission denied` | 「审批自动化」不是这张 Base 的文档应用 | 按本章开头的前置步骤添加文档应用并授予「管理」权限 |
| 一部分字段暂停 | 有字段被跳过，其余仍在同步 | 去「维护字段」修，不要反复点立即拉取 |

> 单轮拉取上限每表 20,000 行；定时拉取间隔由运维配置，默认 15 分钟。Excel 导入源没有「体检结果」页签。

## 2. 修改飞书审批定义

### 2.1 打开并编辑

1. 打开 <https://www.feishu.cn/approval/admin/approvalList?devMode=on>。
2. 找到目标审批，点编辑，进入「表单设计」增删控件；「流程设计」改审批人。
3. **必须使用标准审批流程，不要选「自由流程」**，自由流程无法用接口提单（错误码 1390013）。
4. 改完点右上角「发布」。只有已发布的定义才能被系统提单。

> 控件名称建议与提交表里的列名一致，系统默认按名称自动匹配；也可以在系统向导里手动选列。

### 2.2 哪些控件能自动填写

| 类别 | 控件 |
|---|---|
| **可自动映射** | 文本、多行文本、数字、金额、公式、日期、日期区间、单选、多选、人员、部门、电话、明细、附件、图片、关联审批、请假/加班/外出组（仅官方支持的子控件） |
| **不展示、不映射** | 说明、引用多维表格、流水号、收款账户、出差控件组、补卡控件组、旧控件组、换班控件组 |
| **需要人工准备值** | 地址、旧版附件、文档 |

注意：

- 必填控件必须映射到列，否则配置保存不了。
- 「不展示、不映射」的控件如果设成必填，也会保存失败；改成非必填或换控件。
- 金额控件的币种只能从审批定义里金额控件设置的币种取，系统映射表里没有币种列。
- 附件只自动搬运新版附件和图片；图片单文件 ≤10 MiB，其他附件 ≤50 MiB。
- 关联审批控件只认实例 Code 或飞书 AppLink。

### 2.3 外部选项控件

在表单设计里点单选/多选控件，在右侧选项设置里选「使用外部选项」：

| 审批后台字段 | 填什么 |
|---|---|
| 请求 URL | 数据源「凭据配置」里的接口地址 |
| Token | 该字段的 Token |
| Key（加密用） | 留空 |
| 联动参数（参数代码） | 带级联时填「联动 key」 |

填完点「校验数据」，能拉到选项才算接通。字段超过 100 个时，审批控件可能需要开启分页/搜索能力。

级联要父子两个控件都配：父控件正常配外部选项；子控件填联动 key，并指定依赖父控件的哪个值。

### 2.4 发布并复制审批定义 Code

1. 发布后回到审批列表，点编辑图标进入编辑页。
2. 复制浏览器地址栏里 `definitionCode=` 后面那一段，形如 `E3254848-D172-4169-B03E-744E7CD11F06`。
3. 地址里的 `id=` 纯数字只用于「打开审批定义」跳转，不参与提单。
4. 在本系统建配置时，可以只粘 Code，也可以粘整条编辑页地址；不要粘审批列表页地址。

改过表单或流程后：先重新发布，再回本系统编辑配置、重新「预览控件」并保存，否则会报「审批定义快照与字段映射不一致」。

### 2.5 常见错误

| 错误 | 意思 | 怎么办 |
|---|---|---|
| `1390015` | 审批定义已停用 | 回审批后台启用并重新发布 |
| `1390002` | Code 不对 | 从编辑页地址栏重新复制 |
| `1390013` | 自由流程不支持接口提单 | 改用标准审批流程 |
| 「必填控件没有配置有效的多维表格列」 | 控件名与列名对不上，或必填未映射 | 系统向导第 2 步手动选列 |
| 「快照与字段映射不一致」 | 审批定义改过控件 | 编辑配置，重新预览并保存 |
| 「选项无法从列里派生」 | 单选/多选文案对不上 | 两边文案逐字一致，或改用外部选项 |

## 3. 配置提交使用的多维表格

这一步用飞书审批的数据自动建一张表，再把它变成可提交的表。

1. 打开飞书多维表格，点左下角「新建」。
2. 点「导入/同步数据」。
3. 选择数据来源「飞书审批」。
4. 选择目标审批定义。
5. 时间范围随便选。建议选一个没有数据的时间段，建出来就是空表；如果带出了历史审批记录，建好后删掉，避免批量提交时把旧记录也提交。
6. 点「下一步」。系统会带出该审批的全部字段。
7. 如果这个审批有「明细」控件，点「拆分同步」，把明细拆到子表；没有明细就不用点。
8. 点「保存并同步」。表格建好。
9. 点表格名字右边的「…」，选择「移除配置」。这一步是断开审批同步，让表变成普通可编辑表；不移除的话，同步会继续往这张表写数据。
10. 把「审批自动化」加为这张表的文档应用：点右上角「…」→「更多」→「添加文档应用」→ 搜索「审批自动化」→ 添加，并把权限设为「管理」（也可能显示为「可管理」）。系统要用这个应用读写这张表；没加会在系统配置时报权限错误或读不到记录。
11. 新增三个字段：

| 字段 | 类型 | 用途 |
|---|---|---|
| **申请人** | 人员 | 系统配置里的「申请人员字段」；创建审批后系统把申请人写回这一列。同步表自带的发起人通常是文本，不能代替这一列。 |
| **审批编号** | 文本或超链接 | 系统配置里的「回填字段」。文本列能直接看到编号；超链接列能点开审批单，但失败原因不会写进格子。如果同步表里已有同名列，换个名字，例如「派发编号」。 |
| **批量提交** | 复选框 | 系统配置里的「批量范围复选框列」。只有勾选且审批编号为空的行才会被批量提交。不做批量提交可以不加，但建议加。 |

12. 如果第 5 步带出了历史记录，选中删除，只保留需要提交的行。
13. 同步表里已有的「审批状态」「当前处理人」「完成时间」等列不要删。字段类型匹配的话，系统配置第 3 步可以直接把它们选为扩展回填列，不用新增。

> 行内提交按钮不在这三个字段里。第 5 章建工作流时，再在表里加一个「按钮」类型字段。

## 4. 在本系统配置审批派发

### 4.1 新建配置

进入「审批派发」→「配置」→ 右上「新建配置」。

**第 1 步：选来源数据表**

- 粘贴第 3 章那张表的 Base 链接或 Base Token，点「拉取数据表」，选数据表。
- 拉不到时手填数据表 ID（链接里 `tbl` 段）。

**第 2 步：预览审批控件并映射**

- 粘贴第 2 章拿到的审批定义 Code 或编辑页地址，点「预览控件」。
- 逐行选择「审批控件 → 多维表格字段」。必填控件必须选列；可选控件可以「不映射」。
- 使用外部选项的控件还要选「外部选项来源」（数据源 + 字段）。

**第 3 步：指定申请人、回填列与批量范围**

| 界面字段 | 选哪一列 | 注意 |
|---|---|---|
| 申请人员字段 | 第 3 章新增的「申请人」人员列 | 必须是人员列；同步表里的文本发起人不能替代 |
| 回填字段 | 「审批编号」或「派发编号」 | 文本或超链接；超链接列失败时格子不写原因 |
| 批量范围复选框列 | 「批量提交」复选框 | 用页面按钮批量提交时必须选；不选会提交整张表所有审批编号为空的行 |
| 申请状态回填列（可选） | 同步表里的审批状态列 | 文本或单选 |
| 审批流程回填列（可选） | 可用文本列 | 文本或单选 |
| 发起时间/完成时间回填列（可选） | 对应日期列 | 日期 |
| 发起人部门回填列（可选） | 文本列 | 文本 |
| 当前处理人回填列（可选） | 人员列 | 人员 |
| Base 时区 | 默认北京时间 | 一般不用改 |

**第 4 步：核对并创建**

核对摘要，点「创建配置」。校验失败会一次报全原因。新建配置默认已启用；启用只表示允许受理新的派发请求，仍需飞书工作流触发。

### 4.2 接入数据：拿派发链接和模板

进入配置详情 →「接入数据」：

| 项目 | 用途 |
|---|---|
| 派发链接 | 形如 `http://47.109.148.207:18654/api/v1/feishu/approval/dispatch/<配置标识>`。以页面复制为准，不要手动改协议；必须是飞书能访问的公网地址。 |
| 访问 Token | 每条配置独立一份，放在请求体 `token` 字段。和数据源 Token 不是同一个。 |
| 单行模板 | 给行内按钮用，带 `record_id`。 |
| 批量模板 | 给页面按钮用，不带 `record_id`。 |

单行模板：

```json
{
  "token": "<访问 Token>",
  "record_id": "<触发记录 ID>",
  "applicant": "<发起人姓名>",
  "requested_by": "<触发人标识>"
}
```

批量模板：

```json
{
  "token": "<访问 Token>",
  "applicant": "<发起人姓名>",
  "requested_by": "<触发人标识>"
}
```

- 模板里的 `<访问 Token>` 要换成实际 Token，它是固定字符串，不用变量。
- `applicant` 传姓名；如果表格的申请人列已经填好，请删掉这个字段，让系统读表格。
- `requested_by` 只用于派发记录展示，不影响审批。
- 旧模板里带 `Authorization`、`base_token`、`table_id` 的写法已作废，以「接入数据」页复制的为准。

### 4.3 启用、编辑、删除

- 编辑只能改名称、时区、字段映射、扩展回填列、批量范围列和审批定义链接；来源表、审批定义、申请人列、回填列不可改。
- 删除会清掉配置、字段映射和该配置全部任务行，仅派发请求记录保留；有「待处理/创建中/已创建/待人工核查」任务时会拒绝删除。
- 删除前先停用或删除飞书表里的按钮和自动化，否则旧链接会报 `40401`。

### 4.4 派发记录与状态

结果分四类：成功、等待、已受理、失败。批量「已受理」只代表入队，逐条结果点开「查看任务」看。

任务状态：待处理、创建中、已创建、已回填、终止、未通知、待人工核查。

- **等待**：补数据后再点。
- **终止**：修配置或数据，清空回填列后再点。
- **待人工核查**：先去飞书确认是否已建单，系统不会自动重放。
- **已成功建单的记录不要清空回填列重试**；系统有固定编号，重复点不会多建单。

通知：成功/失败会发给申请人或记录创建人；批量逐条发；一条都没命中会给点击人发「【批量提交未处理任何记录】」。

## 5. 建按钮/自动化并测试

### 5.1 行内按钮（单条提交）

1. 在提交表加一个「按钮」类型字段。
2. 表格右上「自动化」（部分版本叫「工作流」）→ 新建 → 触发器「按钮点击时」→ 选这个按钮字段。
3. 添加「发送 HTTP 请求」：POST 派发链接；请求头 `Content-Type: application/json`（不需要 Authorization）；请求体粘贴单行模板。
4. 先把 `<访问 Token>` 换成实际 Token；再把 `record_id` 换成「记录 ID」变量，`applicant`/`requested_by` 换成「触发人」变量。做法：删掉尖括号里的占位文字，光标留在双引号里面，再点「插入变量」选对应字段；不要手打变量名。
5. 如果表格申请人列已经填好每行真正的申请人，把 `applicant` 整行删掉。
6. 响应类型 JSON，响应示例 `{}`；保存并启用。
7. 测试：填一条记录的全部必填内容，点行内按钮 → 几秒后「审批编号」列出现编号 → 系统「派发记录」出现「成功」。

### 5.2 页面按钮（批量提交）

1. 在仪表盘/应用页面加一个「按钮」组件。
2. 新建自动化，触发器「页面按钮点击」，选中这个按钮。
3. HTTP 请求同 5.1，请求体用批量模板，不带 `record_id`，先替换 `<访问 Token>`。
4. 如果每行申请人不同，删掉 `applicant`。
5. 保存并启用。
6. 使用：勾选「批量提交」列 → 点页面按钮 → 响应「已受理」→ 系统「派发记录」展开「查看任务」逐条核对。
7. 页面按钮省略 `record_id` 会唤醒所有启用配置的待处理队列，不只当前表；只在确实要处理整个队列时用。

### 5.3 HTTP 节点可照抄

```
POST http://47.109.148.207:18654/api/v1/feishu/approval/dispatch/<配置标识>
Content-Type: application/json
```

单行/批量请求体见 4.2 模板；`record_id`、`applicant`、`requested_by` 用工作流变量。工作流界面里通常显示为 `$.step_btn.recordId` 和 `$.step_btn.user`，以实际显示为准，用「插入变量」选，不要手打。

成功响应 `code: 0` + `data.status: succeeded` + `serial_number`；业务失败仍可能是 HTTP 200、`code` 非 0。**以系统派发记录为准，不要只看飞书工作流历史。**

常见错误码：

| code | 含义 |
|---|---|
| `40401` | 配置不存在，核对派发链接 |
| `40402` | 还没签发访问 Token |
| `40301` | 访问 Token 无效，轮换后没更新工作流 |
| `40302` | 配置已停用 |

### 5.4 测试清单

1. 单条：点行内按钮 → 编号出现 → 派发记录「成功」。
2. 打开飞书「审批」→「我发起的」，能看到这张单，申请人、字段正确。
3. 配了扩展回填列的，看状态、处理人是否开始变化。
4. 批量：勾选 1～2 条 → 点页面按钮 → 「已受理」→ 任务逐条「已回填」。
5. 如果没成功：先看系统派发记录的说明和回填列文字；再看飞书工作流是否启用、地址和 Token 是否与「接入数据」一致。

### 5.5 限制与坑

- 「已受理」不等于审批已创建。
- HTTP 节点 60 秒超时；超时先查表，再决定是否重试。
- 派发链接必须是公网地址，飞书访问不到内网。
- 轮换访问 Token 后要同步更新工作流。
- 一张数据表只能建一条配置。
- 批量扫描每轮最多 10,000 行；创建审批约 90 次/分钟，大表要等。
- 勾选只在受理时生效，取消勾选不会撤回已入队任务。
- 系统不能撤回已创建的审批；要撤回只能在飞书逐单处理。

## 6. 常见问题

**Q1：审批下拉框没有选项？**
查数据源和字段是否启用、体检是否通过、审批控件的地址和 Token 是否与「凭据配置」一致；错误码对照见 1.4。

**Q2：点按钮没反应 / 没出现审批编号？**
先看系统「派发记录」：没有记录 = 请求没到系统；有「等待」= 数据不全；有「失败」= 看说明和回填列文字。看不到「审批派发」菜单就找业务管理员代查。不要只看飞书工作流历史。

**Q3：显示「已受理」是不是每条都成功了？**
不是。「已受理」只代表入队，逐条结果在「派发记录」里展开「查看任务」。

**Q4：审批状态列一直不更新？**
确认配置第 3 步选了对应的扩展回填列且类型正确；再找系统管理员确认审批状态回流配置是否正常。

**Q5：会不会重复建审批单？**
不会。系统给每条记录记了固定编号，同一条记录重复点击不会建第二张单；但清空回填列重试、或换审批定义重建配置，可能被当成新记录再建一单。

**Q6：表格改了列名、加了列怎么办？**
多维表格数据源按字段 ID 走，改名不影响；Excel 导入源的列名就是身份，改名要重新导入。审批配置的映射变了，要编辑配置重新预览并保存。新增列后，数据源侧用「维护字段 → 添加」，审批配置里重新映射。

**Q7：能换审批定义或来源表吗？**
不能。配置建好后这几项固定，只能删除重建。

**Q8：Token 轮换后忘了更新会怎样？**
审批控件会报 `40102`，飞书工作流会报 `40301`；分别把新 Token 粘回审批后台和飞书工作流即可。
