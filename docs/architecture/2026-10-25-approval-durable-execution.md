# 审批持久执行与未知结果

本次修复按三个可验证阶段推进。这里记录目标契约；未完成项不能当作当前能力。

1. 持久受理与认领：复用任务表保存单条意图，请求日志保存批量展开意图。HTTP 先提交意图，再与 worker 使用同一原子认领；通常的同步成功响应不变。内存通道只负责唤醒，丢信号不丢工作。认领复用 `worker_id`、`lease_until`、`available_at`、`attempts`，另加单调执行代次；写回必须匹配 owner、代次与有效租约。播种不能重置活动、未知或终态任务。
2. 外部结果未知：每次创建或回填出站前持久记录阶段；创建成功立即保存实例编号。取消、超时、租约过期以及本地确认失败不自动重发写请求。未知创建只读按 UUID 核查，空结果和读取失败均不证明不存在。多维表格没有远端 fencing，未知回写暂停自动写者，需要人工核对并确认旧请求不再在途后恢复。配置删除不得销毁这些恢复证据。
3. 通知：新增纯绑定通知 outbox，结果与通知意图在同一事务落库。结果代次与稳定消息 UUID 区分历史反馈；通知扫描独立于任务业务终态。飞书消息去重窗口之外的未知发送不能自动声称已送达或无限重发，须进入人工核查。

验收使用独立 MySQL 连接与受控 HTTP 回放，覆盖双实例竞争、旧 owner 写回、远端成功后本地确认失败、通知失败独立重扫和历史反馈压制新结果。每个新守卫做摘除变异。测试不访问真实飞书，不执行生产迁移或部署。

## 未知结果的人工恢复边界

`review` 不是确定的业务失败。对多维表格写入，HTTP 超时、进程退出以及当前读回值相同，都不能证明旧请求不会晚到。先停止全部旧版本与新版本写者，保留任务 UUID、实例编号、执行代次与写入阶段，再结合飞书审批记录及多维表格修改记录核查；无法确认在途请求已经结束时继续保留 `review`，不能清空单元格或把任务改回 pending 来“试一下”。业务负责人确认远端最终结果并接受恢复动作后，才能有针对性地恢复；本次代码修改不包含任何生产恢复写入。

未知创建只能按持久 UUID 读取。查到实例可保存其编号并恢复后续流程；未查到、权限错误或读取超时都不得触发新建。配置删除与重建不能绕开待执行、在途和未知任务的证据保留。

发布时必须先停止旧写者再启用新协议；旧版本不会遵守新 owner/阶段字段，数据库增加字段本身不能隔离旧进程。租约解决本地执行权，不提供远端 fencing，也不构成严格 exactly-once 保证。
