### 结论一：这个表单里**没有跨控件级联**

9 个「引用多维表格」控件的 `bitableConfig` **只有** `{appToken, tableID, fieldID, fieldName, parentWidgetID}`——
**没有任何 linkage / filter / cascade 配置**，且所有控件的 `display_condition` 均为 `null`。

**表单里没有「费用大类」控件**，也没有任何"选了 A 才显示/过滤 B"的配置。

→ **对这张表单，设计文档 §8-U1b（层级口径）不阻塞**：没有级联要做。
→ 「级联跟随原本绑定的多维表格的逻辑」这句里的"级联"，从数据上看**不存在跨控件形态**；若指的是下面的「组内同行带值」，那是另一回事。

### 结论二：真正的"联动"是**组内同行带值**

同一个 `mutableGroup`（一个「引用多维表格」控件）内的**多个子控件来自该表的同一行**。
最清楚的例子是第 8 组（`widget17802956697790001`「引用多维表格-副本」）：

| 子控件 | 类型 | 绑定的列 |
|---|---|---|
| 币种/Currency | `radioV2` | `fld5PEZ7GP`（**text**，无目录） |
| 汇率/Exchange Rate | `number` | `fldqE39K61`（**number**） |

选了「币种」所在的那一行后，**汇率会带出同行的值**。

> **⚠️ 这是"全部替换成外部选项"的一个硬缺口**：外部选项控件只能提供**选项列表**，
> 无法把同行的另一个列值**带出**到另一个控件。`汇率` 是 `number` 控件、不是选项控件，
> **它无法被外部选项替代**。第 8 组只能拆成「币种用外部选项 + 汇率保持原样或另想办法」。

### 结论三：三个绑定列**不是 select 类型**，没有"字段选项目录"

| 绑定的列 | 类型 | 影响 |
|---|---|---|
| 项目组合/Project Portfolio（`tblipcUMi7HCvFni` / `fldYIFktaL`） | **text** | 无目录，值域只能取**记录** |
| 币种/Currency（`tblhc4e8AL7s3HP1` / `fld5PEZ7GP`） | **text** | 同上 |
| 汇率/Exchange Rate（`tblhc4e8AL7s3HP1` / `fldqE39K61`） | **number** | 非选项控件，不适用 |

→ **对这张表单，设计文档 §8-U1a（目录 vs 在用值）不适用**：能取到目录的只有 select 列，
其余只能取记录里该列的去重值。**值域来源由此确定为「记录」**，不是二选一。
