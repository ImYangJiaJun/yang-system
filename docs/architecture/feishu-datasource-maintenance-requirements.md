# 飞书外部数据源维护 — 需求规格

**日期**：2026-10-23
**状态**：需求已确认，待设计/排期
**范围**：`project/yang-system`，`feishu.datasource` 的 pull（多维表格定时拉取）数据源
**前置阅读**：`AGENTS.md`、`docs/architecture/feishu-datasource-table-config.md`、`docs/architecture/feishu-datasource-table-config-decisions.md`

---

## 1. 背景

多维表格的列会被业务人员增删改。当前系统在远端字段被删除后，自动拉取会在字段名解析阶段整表失败；控制台又没有编辑字段绑定的入口，运维只能删掉整个数据源重建——而重建会换 `source_key`、Token 和数据源 id，导致飞书审批后台里已经配好的 URL/Token 全部失效。

本需求把「数据源维护」收敛为一组**非破坏性**操作：字段被删后可以停用或原地改绑；远端新增字段后可以刷新并选择加入；维护全程不改变飞书侧已经使用的身份与凭据。

## 2. 现状事实（代码核实）

### 2.1 身份链

| 标识 | 作用 | 维护时的约束 |
|---|---|---|
| `feishu_datasource.id` | 表级主键、详情页路由、绑定归属、审计实体 | **不可变** |
| `feishu_datasource_field` 行 | 一条字段绑定 | **不可物理删除**（整源删除除外） |
| `field_id` | 指向 Bitable 列；改名不断链 | **本期唯一允许原地变更的指针** |
| `field_name` | 每轮拉取按 `field_id` 解析回写的缓存 | 可刷新；也是审批装配按列名配对的依据 |
| `source_key` | 飞书控件 URL 路径段；全局唯一 | **不可变**，维护入口不得修改 |
| `token_hash` / `token_cipher` | 每条绑定一份凭据；全局唯一 | **不可变**，维护入口不得轮换 |
| `parent_field_id` | 同表父绑定指针 | 可变，但会改变子树 `option_id` |
| `option_id` | `source_key + hash(文案/祖先链)` 派生 | 不可手改；旧行只停用不删除 |

### 2.2 四个关键现状

1. **改绑目前是破坏性的**：`update_datasource_table` 的差异计算以 `field_id` 为匹配键（`src/addon/feishu/datasource/actions/update_datasource_table.rs:51-82`）。把一条绑定改指到另一个 Bitable 字段，会被判成「新增一条绑定（新 `source_key` + 新 Token）+ 停用旧绑定」，飞书侧必须重配 URL 和 Token。
2. **字段被删 = 整表停更**：拉取第一步一次性解析全部绑定（含父列）的字段名，任一 `field_id` 缺失即整轮失败，失败发生在取快照和写库之前（`src/addon/feishu/domain/pull.rs:349-361`、`src/addon/feishu/domain/bitable.rs:451-513`）。没有单字段隔离机制。
3. **体检结果不可读**：`missing_fields` 只有 `{field_id, source_key}`，没有字段名（`src/addon/feishu/datasource/actions/health_check.rs:95-107`）；前端只能展示技术标识。体检也不检查父绑定、字段重名、字段类型。
4. **控制台没有维护入口**：编辑对话框只改名称（`frontend/src/features/feishu/components/DatasourceEditDialog.tsx:1-18`）；配置向导只有创建模式（`frontend/src/features/feishu/components/DatasourceTableWizard.tsx:275-299`）；已有数据源没有刷新字段、加字段、停用/启用、改绑的 UI。

## 3. 目标与非目标

### 3.1 目标

- **G1 可修复**：远端字段被删后，业务人员能在控制台停用该绑定或原地改绑到另一列；飞书已配的 URL/Token 不变。
- **G2 可扩展**：远端新增字段后，能刷新字段列表并选择加入；存量绑定不受影响。
- **G3 非破坏**：维护全程不改 `datasource.id`、绑定行、`source_key`、Token；绑定层「删除」一律等于停用；写操作有审计和影响提示。
- **G4 可读**：体检、字段列表、错误信息以字段名为主，字段 ID 仅作次要排查信息。
- **G5 不中断**：单个远端字段缺失不再拖停整张表；健康字段继续同步，坏字段被明确标记。

### 3.2 非目标

- 不自动为新增字段创建绑定；不自动停用缺失字段。
- 不自动轮换 Token、不修改 `source_key`。
- 不修改 `option_id` 派生公式；不物理清理历史选项行。
- 不迁移/修改 `datasource.id`；不提供跨数据源搬绑定。
- 本期不做 push / xlsx 源的远端字段维护。
- 本期不做数据源级停用/启用（绑定级停用已覆盖维护诉求）。

## 4. 已确认决策

| # | 决策 | 选择 |
|---|---|---|
| D1 | 远端字段缺失时的拉取行为 | **跳过坏字段及其子树，其余字段继续同步**；其他错误仍按表级失败 |
| D2 | 维护界面的「删除字段」 | **仅停用**（保留绑定行、`source_key`、Token、历史选项） |
| D3 | 本期维护范围 | **仅 pull 模式**；push / xlsx 维持现状 |
| D4 | 改绑/停用父字段 | **阻止保存，要求先处理子级**；不允许静默改变子级 `option_id` |
| D5 | 体检展示 | **字段名优先**，字段 ID 次要；缺失字段显示最后一次成功拉取时的名字 |

## 5. 身份不变量（验收硬约束）

1. 维护操作**不得修改** `feishu_datasource.id`、绑定行 `id`、`source_key`、`token_hash`、`token_cipher`。
2. 绑定层删除=停用；`feishu_option` 行只停用不物理删除（整源删除的现有语义不变）。
3. 不修改 `option_id` 派生公式。父指针变化必须显式告警，因为它会改变整棵子树的 `option_id`。
4. 改绑后旧选项由下一轮补集停用（不删除），历史审批单的 `@i18n@<option_id>` 仍可在库中追溯。
5. 系统内按绑定 `field_id` 建立的引用（门户 `query_field_id` / `exposed_columns` / `result_labels`）必须同步更新或显式阻断，不允许静默丢弃。
6. 审批配置的 `field_map.option_source_key` 指向 `source_key`；改绑不改它，但受影响配置必须在影响面中列出并提示重建选项映射。
7. 每次维护写操作必须在同一事务内追加审计，记录 before/after 的 `field_id`、`field_name`、`parent_field_id`；不记录 token/secret。

## 6. 功能需求

### FR-1 字段维护面板（仅 pull 源）

数据源详情页新增「维护字段」入口，打开后展示：

- **当前绑定**：一行一条绑定，字段名（主）、状态（启用/停用/远端缺失/字段类型不支持/字段名重复）、父字段名、`source_key`（次，可复制）、远端字段类型。
- **可新增字段**：远端存在、本地未绑定的字段，显示字段名和类型；字段 ID 仅作次要信息。
- **刷新字段列表**：重新调用 `list_bitable_fields`，刷新远端字段与绑定状态的比对结果。
- **保存前差异预览**：新增 N / 改绑 N / 停用 N / 无变化 N；涉及父级或 `option_id` 变化时红字警告。

维护操作按绑定逐条提交，每次一个原子写操作，不复用 `update_datasource_table` 的「整份替换、未提交即停用」语义。

### FR-2 改绑（核心）

**定位方式**：以绑定的稳定标识定位（推荐 `{datasource_id, source_key}`，`source_key` 已在投影中且全局唯一）；**不得以 `field_id` 作为改绑的匹配键**。

**写入内容**：原地更新同一绑定行的 `field_id`、`field_name`（按远端当前名刷新）、`parent_field_id`；**绝不写** `source_key`、`token_hash`、`token_cipher`。

**保存前校验**：

1. 目标 `field_id` 在远端字段列表中存在。
2. 目标字段名不与同表其他已绑定字段重名（重名会让按名字取数的接口产生歧义）。
3. 目标字段类型可取值（单选/多选等）；不支持的类型直接拒绝并说明。
4. 目标 `field_id` 未被同一数据源下的其他绑定占用。
5. 父指针不得自指、成环；父必须是同一数据源内的启用绑定。

**保存后行为**：

- 飞书控件 URL 与 Token 不变（`source_key` 未变）。
- 下一轮拉取按新列派生选项；旧选项由补集停用（不删除）。
- 历史审批单引用的旧 `option_id` 仍留在库中，但不再出现在选项接口。

### FR-3 字段被删除后的修复

**体检报告**：`missing_fields` 增加 `field_name`（绑定缓存的上次名字）、`field_type`、`affected_children`（受影响的子字段名列表）。前端文案形如：

> 字段「银行流水摘要」在 Bitable 中已不存在（字段 ID `fldXXX`，标识 `old_rate`）；该字段下有 2 个子字段会一起暂停。

**体检结果直接提供动作**：

- **停用此绑定**：`enabled=false`，保留绑定行、`source_key`、Token、历史选项；出站立即返回 `40301 数据源已停用`；可随时重新启用。
- **改绑到其他字段**：走 FR-2。
- **查看影响**：列出引用该 `source_key` 的审批配置和引用该 `field_id` 的门户。

**父级保护**：

- 若缺失字段是父级，只停用父级会被拒绝；必须先在同一维护会话中把子绑定改指到其他父级或解除父级（后者会改变子级 `option_id`，需二次确认）。
- 若数据源只有这一条绑定：允许停用后保留数据源（零启用绑定），不得强制删除整源。

**恢复语义**：重新启用一条远端仍缺失的绑定必须被拒绝，错误信息说明「远端字段已不存在，请先改绑或保持停用」，避免把表重新拖入坏状态。

### FR-4 新增字段

- 「刷新字段列表」后，远端有、本地无的字段显示为「可新增」；勾选后创建新绑定。
- 新绑定使用**新的全局唯一 `source_key`** 和**新 Token**；存量绑定的 `source_key`/Token 不变。
- 新增后必须能立即复制完整 URL + Token，并保留 `reveal_token` 后续回显能力。
- 新字段与已绑定字段重名时保存前阻止，说明「按字段名取数会取到不确定的列」。
- `source_key` 冲突必须折叠为字段级可读错误（不能冒裸 DB 错误）；推荐由后端生成或校验，复用现有 `tableId_fieldId` 规则。
- 新绑定不影响任何已有飞书控件的 URL/Token；但它是**新控件**，需要在审批后台单独配置。

### FR-5 拉取的字段级隔离（D1）

拉取编排在字段名解析阶段把绑定分区：

| 分区 | 判据 | 处理 |
|---|---|---|
| 可解析 | `field_id` 存在、名字唯一、类型可取值、父链完整 | 正常拉取、派生、落库 |
| 远端缺失 | `field_id` 不在远端字段列表 | 跳过该绑定；其整棵子树一并跳过 |
| 字段名重复 | 该绑定名与远端其他字段重名 | 跳过该绑定及其子树；报告冲突名 |
| 类型不支持 | 字段类型无法派生选项 | 跳过该绑定及其子树；报告类型 |
| 父级不可用 | 父绑定被跳过/停用/缺失 | 跳过该绑定及其子树；报告原因 |

**关键约束**：

1. **子树级跳过**：父绑定被跳过时，所有后代绑定也跳过（不能按「无父」处理，否则会静默改变子级 `option_id`）。
2. **跳过不写库**：被跳过的绑定不派生、不落库、不执行补集停用；其选项保持冻结。
3. **逐绑定空派生守卫**：可解析绑定若派生出的选项为空而本地仍有启用选项，视为可疑（权限/类型/数据异常），跳过该绑定的落库与补集停用，不得静默清空下拉。现有表级空快照守卫保留。
4. **表级状态**：拉取结果必须能区分「全部成功 / 部分成功 / 全部失败」。部分成功更新 `last_pull_at` 并记录被跳过的字段名，不更新「最近同步成功时间」；告警文案必须点名被跳过的字段名。
5. **不阻断健康字段**：部分成功时，健康绑定照常写库并更新 `snapshot_digest`；只有被跳过的绑定冻结。
6. **可恢复**：改绑或停用坏绑定后，下一轮拉取自动恢复；父级修好后，被级联跳过的子树自动恢复。

### FR-6 非破坏性保障与影响面

- 维护接口不接受对 `datasource_id`、绑定行 id、`source_key`、Token 的修改。
- 改绑前反查影响面：
  - 审批配置：`feishu_approval_field_map.option_source_key = source_key`；列出配置名，并提示「改绑后需重新保存配置以重建选项映射」。
  - 门户：`feishu_datasource_portal.query_field_source_key = source_key` 或 `query_field_id` / `exposed_columns` 含旧 `field_id`；改绑时在同一事务内同步更新 `field_id` 引用，或阻止并列出需手工处理的引用。
- 审计：每次改绑/停用/启用/新增记录 before/after、操作人、受影响子字段；不记录 token/secret。
- 并发：保存时携带期望的当前 `field_id` 做乐观校验；与拉取 worker 的 `field_name` 回写冲突时提示「绑定已被他人修改，请刷新」。
- 历史选项：所有维护操作不得物理删除 `feishu_option` 行。

### FR-7 业务人员可读性

- 体检、字段维护、错误信息统一「字段名在前，ID 在后」；字段 ID 放在可折叠的详情或复制按钮里。
- 缺失字段用缓存 `field_name`；缓存为空时显示「（未知字段名）」并附 `field_id`。
- 数据源列表/详情增加「同步已暂停/部分字段已暂停」横幅，直接显示缺失字段名和「去修复」按钮。
- 每个会影响飞书控件的操作，确认框写清：哪个字段、哪个控件、会发生什么、如何恢复。

## 7. 数据与接口要求（需求级）

1. **体检响应**：`missing_fields[]` 增加 `field_name`、`field_type`、`affected_children`；同步更新 `frontend/contracts/feishu-projections.json`、Rust 断言与前端类型。
2. **绑定级 Action**（建议，名称可调整）：
   - `repoint_datasource_field`：按 `{datasource_id, source_key}` 原地改 `field_id`/`field_name`/`parent_field_id`。
   - `set_datasource_field_enabled`：按 `{datasource_id, source_key, enabled}` 停用/启用；启用前校验远端字段仍存在、父链可满足。
   - `add_datasource_field`：新增绑定，生成 `source_key` 与 Token，返回可复制的 URL/Token。
   - 三个 Action 均使用 `feishu.datasource.write`；新增凭据回显复用 `reveal_token` 的权限与审计口径。
3. **现有 `update_datasource_table`**：保留用于标题/坐标/创建路径；维护 UI 不使用它的整份替换语义。
4. **拉取状态**：表级增加可区分「全部成功/部分成功/全部失败」的状态与错误信息；具体列名由设计阶段确定，但必须满足 FR-5 的可观测性与告警要求。
5. **契约**：改输入/输出后重跑 `python scripts/dump_openapi.py`，禁止手改生成物；前端 `pnpm check` 全链通过。

## 8. 验收标准

1. **改绑保身份**：改绑后绑定行 id、`source_key`、`token_hash`/`token_cipher`、`datasource.id` 均不变；飞书 URL/Token 不变。
2. **拉取恢复**：字段被删 → 体检显示字段名 + ID → 停用该绑定 → 下一轮其余字段成功；该绑定选项冻结，出站返回 `40301`。
3. **部分成功**：一个字段缺失时，同表其他字段的 `snapshot_digest` 与选项正常更新；表级状态显示部分成功并点名缺失字段；健康字段不回退。
4. **新增字段**：刷新 → 勾选 → 新绑定（新 `source_key` + Token）；存量绑定 `source_key`/Token 不变；新增后 URL/Token 可复制。
5. **父级保护**：改绑/停用父级时，未处理子级则保存被拒，错误信息点名子字段；处理子级后保存成功。
6. **非破坏**：任何维护操作后绑定行数不减少（整源删除除外）、option 行不物理删除、`source_key` 不变。
7. **可读性**：体检 `missing_fields` 含 `field_name`；前端主展示字段名，字段 ID 仅次要展示。
8. **审计与契约**：每次写操作有审计；OpenAPI/投影/前端契约同步；单测+集成测试覆盖改绑、停用、新增、父级保护、部分成功、字段名投影。
9. **变异检验**：每个新增判断至少做一次摘除式变异，确认对应测试变红。

## 9. 影响面与风险

- **D4 语义变更**：现有「全有或全无」文档与测试需同步修订；表级失败计数、告警、`last_success_at` 语义要重新定义。
- **字段类型/重名**：远端字段类型变化或重名目前会导致静默空派生或整表失败；本次必须显式归类并跳过，不得静默清空。
- **父级变更**：改父指针会改变子树 `option_id`，历史审批单旧值失联；只能通过强提示与「先处理子级」降低误操作。
- **门户引用**：门户按 `field_id` 存开放列；原地改绑不同步会让开放列静默消失，必须在同一事务更新或阻断。
- **审批配置**：`option_source_key` 不变，但 `option_map` 快照可能过期；需要提示重新保存配置。
- **并发**：拉取 worker 与维护写操作可能同时改同一绑定行的 `field_name`/`snapshot_digest`；需要乐观校验或行锁。
- **补唯一索引**：若要补 `(datasource_id, field_id)` 唯一索引，必须先清理重复行；同步器遇到重复值会拒绝启动且不会自动删索引。
