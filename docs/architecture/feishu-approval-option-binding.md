# 审批外部选项按需解析（方案 3）

原配置创建流程把每个外部数据源的全部选项展开成 `option_map`，分页上限为 50 页（5,000 条），并要求文案在整个源中唯一。154,363 条选项超出上限；级联中不同父级下的同名文案也会被误判为冲突。

新配置只保存 `external_binding`：数据源 ID、字段绑定 ID、source_key、源字段 ID，以及从根到叶对应的派发表字段 ID。配置创建只读字段绑定与数据源状态，不读取选项表。固定选项与旧配置的静态 `option_map` 保持原行为；旧配置不会自动转成新绑定，需要重新创建配置。

即时派发和后台任务共用按需解析：按当前行的根级选择确定父 option_id，再逐级按 `source_key + enabled + label + parent_key` 查询。父级必须单选；不同父级下的同名文案可正常使用，同一父级下的重名、缺失、停用和绑定归属变化会明确失败。根级兼容历史 `parent_key` 的 NULL 和空串。文案按原始文本精确匹配，保留前后空格；MySQL 排序规则的近似命中由 Rust 再核对，100 条近似命中时保守拒绝。

在第一次调用飞书创建接口前，将申请人 open_id 与最终 form 原子地存入任务的 `prepared_payload`。并发准备只采用首次落库的快照；重试继续使用它，不随表格内容、选项或申请人变化。数据库失败时不创建审批。即时入口与后台播种通过同一个任务插入函数处理并发唯一键冲突，只有回读到归属一致的任务才继续。

新增结构通过启动时的声明式 Schema 增量同步补齐：映射表的 nullable `external_binding`、任务表的 nullable `prepared_payload`、选项表的 `idx_feishu_option_label(source_key, enabled, label, parent_key)`。旧行默认 NULL，数据不重建；上线会为已有选项表建立索引，应预留建索引时间和磁盘空间。没有配置项或 SQL 迁移文件变更。

代价：派发增加少量按父链深度计的数据库查询与快照存储；配置创建不再验证整个源的所有选项，错误在具体行派发时发现。快照创建后修改表格不会修改该任务的提交内容；修正未提交任务需要显式处理其快照，清空回填列不会清除快照。已经提交的审批仍由飞书 UUID 幂等机制回捞，不能靠清快照改变审批内容。

边界：重试入口仍需读取现有配置、表结构和记录；删除它们可能阻止重试。原有 `record_id` 全局唯一约束未改变，跨表碰撞会拒绝。字段绑定读取仍有限量保护（20 页），限制的是绑定元数据，不是选项数量。系统只更新既有多维表格行。

验证用例在 `approval_binding_tests.rs`：专用 MySQL 测试库内构造 154,363 条选项，验证完整三级父链、同名分支、索引实际使用、旧库补字段/索引并保留旧任务、并发快照、选项停用后的重试、绑定失效和数据库失败不调用飞书。飞书传输采用仓库现有回放桩，未调用生产审批接口。

变异验收记录（2026-10-09）：31 处逐项摘除或反向修改，均使聚焦测试变红；编译失败不计入通过。覆盖绑定歧义、父链环与归属、父级单选、启用状态与父级过滤、精确文案与近似命中上限、旧映射与可选空值、快照形状与首次写入、重试复用、任务归属与状态保护、终态回填、等待态以及申请人/表单快照校验。循环防护采用反向条件，避免测试挂在无限循环中。摘除首次写入的 NULL 条件时，并发快照测试报 `assertion left == right failed`；摘除重试复用时，停用选项后的重试测试失败；摘除终态回填时，回填次数断言失败。

聚焦复现：配置 `YANG_SYSTEM_TEST_DATABASE_URL` 为以 `_test` 结尾的专用库、`YANG_SYSTEM_TEST_REDIS_URL` 为 DB 15 后，运行 `cargo test --lib --locked binding_tests -- --include-ignored --test-threads=1`。该用例会重建飞书测试表，必须与其他真实数据库测试串行执行。
