# 外部数据源：数据补充与重新导入字段配置

日期：2026-11-02

状态：设计待用户确认；尚未实施业务代码或数据库变更。

## 1. 目的与范围

现有 xlsx 数据源缺少几行时，可以手动补充，也可以上传增量文件。今后的批次可以继续追加，不必找齐历史文件重新上传。同时允许在全量重新导入时调整字段集合和父列关系。

本次只扩展 `ingest_mode=xlsx_import` 的数据源，不改变多维表格 push/pull 的业务语义。不写死银行、支行或固定列名。

### 1.1 用户已确认

1. 手动补充采用**可加行的表格表单**，一次提交多行。
2. 文件补充采用追加语义，提供模板下载。
3. 补充遇到重复记录时跳过，不新增，也不覆盖原记录。
4. 字段结构由用户设计；用户选择一列作为补充去重的唯一键，并保存在数据源配置中。
5. 唯一键只约束补充。全量文件中同名、不同父级的记录允许分别保留、派生选项。
6. 补充成功的记录在以后的全量重新导入中仍然保留，不因未出现在全量文件中而停用。
7. 全量重新导入时可以增加、减少字段，修改父列关系。
8. 删除被审批配置引用的字段时拒绝操作，列出受影响的配置。

### 1.2 本设计提出、待随文档确认的选择

- 模板是可直接由 Excel 打开的真正 `.xlsx` 文件，不是改后缀的 CSV/HTML。
- 唯一键先支持**单列**，不是联合键；判重范围为同一数据源。
- 判重忽略首尾空白，保留大小写、内部空白差异，不做模糊匹配或自动改名。
- 旧数据源首次启用补充前，须完整重导一次，建立原始行基线；不从已去重的选项反猜原始行。
- 字段变更导致补充记录缺少新的唯一键值或必要父级值时，须在重导向导内补齐后再提交，不静默丢弃、停用这些记录。
- 除审批引用外，门户正在使用的字段也禁止直接删除，并列出门户；有效的最终父子结构可以整组调整，不强制逐字段删除。
- 配置、原始行和选项投影同一次提交生效；任何校验或写入失败均不部分保存。
- 全量文件无有效记录时拒绝；保留字段派生为空但当前仍有启用选项时也拒绝整次提交，不沿用会让原始行与选项不一致的“只跳过该字段”行为。
- 全量及补充文件均须包含本次全部有效字段的表头，缺列拒绝；单元格可以留空，但补充唯一键和非空子值所需的父级值必须填写。
- 手动/文件补充及新版重导都携带修订号；过期表单明确报冲突并保留输入，不按新配置悄悄解释旧输入。

### 1.3 非目标

不增加通用电子表格编辑器、已有记录的任意编辑/删除、联合唯一键、列类型设计、模糊去重、自动纠错、导入历史版本、回滚中心或新的公开写入入口。修改父级关系不承诺保持受影响选项的旧 id。

## 2. 现状与必须保留的兼容性

### 2.1 id 的真实含义

飞书看到的是 `feishu_option.option_id`，不是数据库自增主键。当前派生输入为同一绑定的 `source_key`、完整父链和去除首尾空白的文本，不依赖文件行号。

- 同一数据源、同一绑定、相同父链和文本重新导入，`option_id` 不变。
- 当前写入是 ODKU 原地更新，正常重复导入也不更换自增主键。
- 改文本、改父级路径或改 `source_key` 会使相应选项及其后代的 id 可能变化。
- 配置的补充唯一键**不参与 option_id 派生**，改唯一键不能顺带换 id。
- 同名且完整父链也相同的多行仍按现有规则折叠成一个选项；“各建一条”指同名但父链不同的选项，不是取消现有投影去重。

依据：`src/addon/feishu/domain/derive.rs:148`、`:173`、`:208`；`src/addon/feishu/domain/option_write.rs:109`。

### 2.2 现有导入不是追加

当前全量导入会停用未出现在本轮文件中的旧选项，且按绑定分别提交。只上传新增文件会停用原数据，所以不能把现有按钮换个名字就当补充功能。

当前也不保存原始记录：`ImportSnapshot` 只是内存对象，落库是每列去重后的选项，`extra` 不包含完整原始行。不同原始行可能投影成同一个选项，不能由投影恢复任意列的唯一键。

依据：`src/addon/feishu/domain/xlsx.rs:497`、`:512`、`:547`；`src/addon/feishu/datasource/actions/import_xlsx.rs:497`。

## 3. 两种写入语义

### 3.1 数据补充：只接受未见过的键

同一份数据源内，按当前配置的唯一键比较：

1. 比较集合包括**当前全量快照的所有原始行，以及全部已保留的补充行**。
2. 本次表格/文件中第一次出现且数据库没有的键接受，后续同键行跳过。
3. 数据库已有同键记录，无论其他列、父级是否不同，补充时都整行跳过，不改其值、来源或父级。
4. 唯一键空值/仅空白的补充行属于错误，不把所有空值当成一种重复，也不生成随机键。
5. 纯重复批次不改原始记录、选项、排序或内容摘要，回执显示全部跳过。
6. 已被全量替换移出的普通快照行不再占用补充键；仍保留的补充行始终占用。

补充前校验全部输入。存在格式错误、缺必需列、非空子值缺父值、超出字段容量等问题时，整次提交不生效，返回行号、列名和原因。错误不伪装成“重复跳过”。

### 3.2 全量重新导入：替换普通快照，保留补充

设本轮全量文件的记录为 `S`，历史手动/文件补充成功的记录为 `A`：

```text
保存的当前记录 = S + A
选项投影       = derive(S + A, 本次确认的字段配置)
```

- 只替换来源为普通快照的原始记录，不删除 `A`。
- `S` 不按补充唯一键去重，允许同键不同父级的记录。
- `S` 与 `A` 也不按唯一键互相覆盖：同一键的两种父链可以同时存在；相同路径/文本仍由现有选项派生折叠。
- 即使补充行后来出现在全量文件中，也不把它自动“转正”为可被下轮删除的普通行，保留属性持续有效。
- 从 `S + A` 派生的完整集合之外，原有普通选项仍按全量语义停用，不物理删除选项。
- 父字段关系改变时，按新关系重新派生补充记录。保留的是记录及有效选项，不是承诺旧父路径的 id 永远不变。

不在选项表再加一个永久粘住的“手工选项”标记：选项可能被多行共享，且父级改变后需要淘汰旧路径。保留原始补充行并重新派生能同时覆盖这两个情况。

**空快照安全规则**：全量文件第一张 sheet 只有表头或没有有效记录时，整次拒绝，不把 `S=空` 当成清空命令。对最终仍启用的每个绑定，若 `derive(S+A)` 为空且当前仍有启用选项，也拒绝整次重导并点名字段。原有“该绑定跳过、其他绑定继续成功”的守卫不保留为新流程成功路径，否则新原始行和旧投影会分叉。用户确实要移除一列时，走显式减字段和引用检查；本次不提供清空数据源操作。新源及原本就没有选项的列允许继续为空。被明确移除的列不适用保留字段的空投影守卫。

### 3.3 去重口径及配置变更

- 去重键为 `trim(配置列的解析文本)`，与本轮解析/手动表单采用同一文本规范化；不截断键值再比较。
- 存储 SHA-256 完整摘要用于检索，命中后仍比较实际规范化键值，不能把摘要碰撞当重复。
- 不建立 `(datasource_id, 唯一键值)` 的数据库唯一约束，因为全量同键行是合法数据。
- 修改去重列时，基于持久化原始行重算检索值；不删、不合并历史记录。新规则只决定今后补充是否重复。
- 全量行的去重列允许空值并给出计数提示，这些行不参与键检索；补充行的去重列必须有值。
- 更换去重列后若已有补充行缺值，必须补齐才允许应用配置。

## 4. 最小数据模型

### 4.1 数据源配置

在现有数据源配置上增加：

| 字段 | 语义 |
| --- | --- |
| `unique_key_field_id` | 可空；启用补充时必须选择一个有效字段。使用字段身份，不存中文固定名称 |
| `row_snapshot_ready` | 默认 false；是否已保存完整原始行基线 |
| `revision` | 配置/数据成功写入后递增，用于拒绝过期提交 |

唯一键候选来自用户保留的字段集合；不能指向已移除字段。已配置唯一键后移除该列时，须同一提交选择新的唯一键并通过补充记录校验，不能留悬空配置；本次不提供“清空已配置唯一键/关闭补充”的独立功能。

基线与唯一键是独立状态：

| `row_snapshot_ready` | 唯一键 | 行为 |
| --- | --- | --- |
| false | 空或已选 | 旧源状态；读选项正常，补充拒绝；需成功全量重导 |
| true | 空 | 已保存原始行但尚未启用补充；允许正常重导，补充拒绝；可选择唯一键后启用，无需再传同一文件 |
| true | 有效列 | 可补充；换键前重算全部原始行的检索值并校验补充行 |

唯一键单独选择/更换只影响检索、不变更字段图，可锁内基于原始行原子重建键索引；如补充行缺值，须转入带补齐步骤的重导流程，不能部分改键。旧客户端省略新配置时，使用已有字段与唯一键正常全量重导并建立基线；没有唯一键则保留为空，不替用户选列、不拒绝这次导入。

### 4.2 原始记录

新增一张 `feishu_datasource_record` 表，按仓库“一张业务表一个绑定 module”方式注册，不暴露通用 CRUD：

| 字段 | 语义 |
| --- | --- |
| `id` | 内部记录主键，不向飞书充当选项 id |
| `datasource_id` | 归属数据源 |
| `origin` | `snapshot` 或 `supplement`；手动、文件补充都属于后者 |
| `sort_order` | 本来源内稳定顺序；快照在前，补充按提交顺序在后 |
| `cells_json` | 原始解析文本的字段→值映射，含配置的唯一键列 |
| `key_hash` | 当前唯一键的完整摘要，可空，索引检索而非唯一约束 |

索引覆盖按数据源/来源顺序读取、按数据源/键摘要检索。保留记录创建时间等项目已有审计元数据，确切字段类型由实现者按框架已有能力选择。

持久化全量与补充的配置列值，不保存上传文件二进制、不承诺保存未配置的列。已保存补充记录中的旧列值不因移除字段而立即抹掉，便于重新启用同一列；它不再参与当前选项输出。

选项表继续是可重新派生的投影，不改其 id 公式，也不把原始行 id 塞进 option_id。

### 4.3 旧数据源升级

旧源 `row_snapshot_ready=false` 时：

1. 原有取选项与审批照常工作，不因升级自动停用。
2. 补充入口提示“请先完整重新导入并选择唯一键”；服务端同样拒绝绕过。
3. 完整重导成功后，保存原始行、字段配置和选项，置 ready；若本次选择了唯一键则同时建立键检索，否则保留空键状态。
4. 即使内容命中旧 `snapshot_digest` 的 unchanged 快路径，也必须建立原始行基线，不能跳过。
5. 未能重传旧文件时，不伪造空基线，不宣称可以可靠补充判重。

之后原始行与选项同源保存；不再需要每次补充都上传旧文件。

## 5. 重导字段配置

### 5.1 提交完整的最终配置

重导流程提供文件表头、现有字段和本次差异；用户确认：保留/新增/移除哪些列，每列的父列，以及补充唯一键。

沿用现有 `field_id` 匹配和绑定差异计算：

- 保留字段原有 `source_key` 和访问凭据不变。
- 新增字段才分配新 `source_key` 与凭据，沿用全局唯一校验。
- xlsx 列名是字段身份；本次不增加自动列重命名。改列名视为移除旧列、新增新列，必须经过引用保护。
- 移除字段是退出当前有效配置并停用其选项，保留必要的绑定身份供再次启用；不执行数据库物理删列。
- 同名字段重新启用时优先复用已有绑定，不悄悄换 source_key。

最终图必须无环、无自引用，所有父列都在最终有效集合中。允许同一提交移除一整棵无外部引用的子树，或移除父列并给保留子列改父；不能简单用“目前还有子列”一律拒绝合法整组变更。

**表头完整性**：本轮全量文件必须包含最终所有保留/新增字段的列名，包括唯一键列；不允许以“保留字段但文件无此列”暗中把普通记录整列置空。文件缺列时应修正文件，或显式从最终配置移除该字段并通过引用保护；额外列可忽略并提示。新源、手动补充和文件补充使用同一配置列集合，不能模板有一套、解析又有一套。

**写入口边界**：xlsx 源的增/减字段、启停字段、修改父关系只允许通过本次原子重导流程；现有直接配置更新/字段维护接口若请求这些结构变更，明确拒绝并引导重导。名称等纯展示属性继续允许直接修改；唯一键单独选择/更换按 §4.1 的原子索引流程处理。不能让旧 API 仅改配置而不重建原始行/投影。push/pull 源仍按原有字段维护规则工作。

### 5.2 引用保护

对本次待移除/停用字段统一作反向引用查询，错误结果至少包含字段、引用类型、配置 id/标题及可定位入口：

1. 审批 `approval_field_map.option_source_key`：被任何现存配置引用即拒绝，不只检查启用的审批配置。
2. 门户的查询字段、暴露列、结果标签：仍被使用即拒绝并列出门户，不静默裁列。
3. 父子关系与唯一键：以本次最终配置为准校验，不留下孤立子列或悬空键。

失败时整次重导不写任何配置/数据。先在相应配置中解除引用，或取消本次减字段，再重试。

保护放在共享的配置写入边界，覆盖重导、直接配置更新、停用字段等可达入口，不能只在前端按钮检查。原有 public 入站写入口不得成为绕过 xlsx 原始行/投影一致性的通道。

可复用：`src/addon/feishu/domain/field_maintenance.rs:577` 的审批反查；门户引用依据同文件 `:487` 的现有同步机制补齐。以代码核实实际字段名，不自行另建引用登记表。

### 5.3 改父关系与补充记录

- 保留绑定 source_key，仅调整父列配置；重置/重算相关内容摘要并重建受影响投影。
- 向用户列明受影响列、审批配置，明确提示受影响选项 id 可能改变。
- 当前审批外部选项在派发时重新解析，不把“所有审批必须重新保存”作为常规要求；已播种、尚未提交的聚合组可能因签名变化暂停，需要重新批量点击。
- 校验全部保留补充行：新增普通列可以暂为空；已有非空子值若缺新父链值，或新唯一键缺值，则在重导流程提供这些记录的补齐表格。
- 补齐表格仅用于本次变更所必需的缺值，不扩展为任意记录编辑器。若用户取消或仍缺值，整次变更不生效，旧数据保持可用。

## 6. 后端流程、一致性与并发

### 6.1 复用与接口边界

复用已有 xlsx 表头探测、上传限制、解析和派生机制，不另写一套解析器：

- 现有全量导入接口扩展可选的最终字段/唯一键配置与 `expected_revision`。省略配置仍表示按现有配置全量重导，不把旧调用悄悄改成追加。
- 新增受登录及 `feishu.datasource.write` 保护的多行补充 Action，必须接收 `expected_revision`。
- 文件补充复用导入处理链，但明确选择 supplement 模式，同样必须携带 `expected_revision`；模式不能由文件名称猜测。
- 新增模板下载 Action，用现有受保护下载协议返回真实 xlsx。
- 获取数据源详情时返回配置、ready、revision；沿用现有导入进度能力和必要状态字段。

具体 Action 命名与路径由实现者按已有风格确定；保持“一 Action 一文件”。两种补充入口必须汇入同一个判重/保存机制。

### 6.2 原子提交

解析、格式校验可在事务外进行。最终写入以数据库中该数据源行的写锁串行化，并检查修订号；不能依赖仅进程内的 `ImportGuard` 保证多实例安全。

- 补充：锁内重读配置并先校验修订号，过期则整次拒绝，不把旧输入按新字段/父链/唯一键解释；通过后读取判重集合，过滤重复，保存新补充行并生成一致的选项投影，再更新 revision。
- 并发补充：两个相同修订号提交只能有一个先提交，另一个明确报修订冲突并保留原输入；刷新、用户重试后按当前键判重跳过。不能为了自动重试而忽略配置可能改变。
- 新版重导携带修订号。为兼容旧客户端，旧式请求省略配置和修订号时，解析前由服务端捕获当前 revision，再在事务锁内比对；若期间有写入则报冲突，不取提交时的新配置覆盖解释已解析文件。
- 全量：锁内重读全部保留补充行，应用补齐值，保存最终配置、替换 snapshot 原始行、更新键检索、投影 `S+A`、停用补集，更新 revision。
- 相关绑定、原始行、选项和摘要使用同一个数据源级事务；失败全部回滚。不能先保存字段配置再请求导入。
- 其他实例读到的是提交前或提交后的完整状态，不是“新配置配旧选项”。
- 审批/门户新增或修改引用时须与字段移除使用相容的数据库锁及有效性校验，避免“查完没有引用后，另一个事务刚好新增引用”的竞态。多源锁按稳定顺序获取，避免倒序死锁。
- 已存在的直接 API 写入必须经过相同边界，或者明确拒绝对 xlsx 源进行不维护原始行的写入。框架内已有共享能力优先复用。

原始行/选项处理按主键游标分页及分片批写，不使用 2,000 行 all_pages 作为“全部”。完整投影之后再求补集；若安全容量上限使完整处理无法完成，明确报错回滚，不能返回成功却遗漏数据。

`ponytail:` 本次接受按数据源串行化和全量重导时 O(n) 重建，不建分代快照/后台切换平台；仅在真实规模证明锁时长或事务容量不合适时，再设计暂存后原子切换。

### 6.3 排序、摘要与回执

选项顺序继续由全量文件首次出现顺序决定，补充行追加在后；补充不把已有选项移到开头。使用同一完整记录顺序派生，不能把每批 sort_order 都从零写回。

内容摘要反映当前有效投影及派生配置；补充后不能遗留一个可错误短路后续全量导入的旧摘要。唯一键索引与原始行建立不受选项摘要 unchanged 路径跳过。

回执区分：输入记录数、新增原始记录数、重复跳过数、补充保留数、各字段新增/停用选项数及失败原因。记录数不等于选项数，因为多个记录可能共享同一个父选项。

## 7. 控制台与模板的功能约定

### 7.1 数据补充

仅对可写 xlsx 源提供“数据补充”：

- 手动：按当前有效字段生成表格；支持加行、移除尚未提交的行；唯一键列明确标注，父子错误定位到单元格。
- 文件：下载当前数据源模板、选择 xlsx、提交追加；明确文案“重复整行跳过，已有数据不覆盖”。
- 缺基线/唯一键时给出重导入口，不能只禁用按钮却不解释。
- 提交期间防止重复点击；重复网络提交仍由服务端判重保证不新增第二份。
- 成功展示新增/跳过回执，刷新现有选项预览。保留用户输入直至成功或明确取消。

### 7.2 全量重导

在现有重新导入流程中增加字段配置确认和变更摘要，依次完成：文件及表头探测 → 最终字段/父列/唯一键配置 → 引用及补充记录校验 → 必要补齐 → 一次确认提交。

文案明确：“替换普通导入数据；已补充数据保留。”减字段或改父关系显示相应影响，不宣称 id 永远不变。

### 7.3 模板

- 第一张 sheet 第一行是当前数据源的真实列名，包含全部有效字段和唯一键列，不要求用户填写 option_id/source_key。
- 表头顺序与手动表格相同；第一张 sheet 不放可被误当数据导入的示例行。
- 唯一键/父列关系及填写说明可放第二张 sheet，数据解析仍沿用只读第一张 sheet 的契约。
- 服务器从同一份字段配置生成模板和校验必需列，不能分别硬编码。
- 老模板缺新增必需表头时给出缺列清单并拒绝；这里“必需表头”指**全部当前有效字段**，不是只要求唯一键/父链。多余旧列沿用忽略规则并提示，不暗中恢复已移除字段。
- 普通非键列的单元格可留空；若子列非空则其整条父链必须非空，补充唯一键值不得为空。手动表格自动生成全部列，遵循同样的单元格校验。
- 用户列名写成普通文本，不能被 xlsx 写库自动解释成公式。下载文件名及响应头按现有安全规则生成。

后端生成而非前端塞入大型 xlsx 库。实现时先检查已安装能力；若没有写库，选择符合本项目 MSRV/许可证的最小可靠依赖，不手工实现 Office ZIP/XML，不伪造格式。依赖变动须按项目要求做冷 MSRV/依赖策略验证。

## 8. 安全与实施约束

- 复用现有 datasource.read/write 权限、鉴权和审计机制，不新增管理 Token 公共补充端点，不给前端直写数据库。
- 文件上传沿用当前类型/大小/解压/单元格预算及错误处理；新模式不能绕过这些保护。
- 原始数据不写普通日志；审计记录操作人、数据源、模式、字段变化和计数，不整表打印。
- 新表/列经声明式 TableDefinition 同步，不新增 SQL 迁移文件；移除配置字段不等于删物理数据库列。
- 本文只设计，不授权执行任何数据库写入。后续本地集成测试、DDL、生产操作仍按用户规则明确范围并二次确认。
- 不自动提交、不部署、不推送。实现后按约定重导 OpenAPI/前端契约，不手改生成物。

## 9. 验收标准

| 场景 | 必须满足 |
| --- | --- |
| 相同 xlsx、绑定与父链不变重复全量导入 | 原选项 id 不变 |
| 手动加多行，混合新键、库内重复键、批内重复键 | 只保存新键；重复整行跳过，原值不变 |
| 文件补充同一批两次 | 第二次新增 0，无排序/内容变化 |
| 两个实例同时补同键 | 只接受一次，另一个跳过或收到明确可重试冲突，不产生重复记录 |
| 补充以后重导不含补充行的完整文件 | 补充行及当前父链下的有效选项保留 |
| 全量含同键不同父级 | 原始行均保留，派生各自父链下的选项 |
| 全量普通行消失但同键补充行还在 | 只移除普通快照身份，补充记录仍在 |
| 全量精确命中已有补充行，下一轮又不含它 | 补充身份不丢失，仍可取到 |
| 修改去重列 | 历史行不去重/删除；新补充按新列判重，选项 id 不因此变化 |
| 旧源首次启用 | 无基线不能补充；相同内容重导也成功建立原始行基线 |
| 旧客户端无唯一键重导 | 成功后 ready=true、key=空；补充仍拒绝，后续选键不必重传文件 |
| 空文件/保留字段意外全空 | 整次拒绝并指出原因，不出现原始行已替换但旧选项被静默保留 |
| 旧表格/文件提交时修订号已过期 | 明确报冲突并保留输入，不按新配置静默丢列 |
| 文件缺任一最终有效列 | 列出缺列并整次拒绝；不把缺列解释为减字段 |
| 直接 API 尝试变更 xlsx 字段结构 | 拒绝并引导原子重导，不能只写新父关系 |
| 增字段、移除无引用字段、有效的整组改父 | 配置、全部原始行与投影一次生效；source_key 尽量复用 |
| 移除审批/门户引用字段 | 服务端拒绝并列出实际配置，数据库状态不变 |
| 同时创建引用与移除字段 | 不留下指向无效字段的已提交配置 |
| 新父链或新唯一键在补充行中缺值 | 显示需补齐记录；取消/失败不丢原数据 |
| 配置后上传/落库失败、陈旧 revision 提交 | 不部分保存、不覆盖新提交；回执可归因 |
| 大于 2,000 行、超过原补集上限 | 不把分页截断当全量；完整处理或明确失败回滚 |
| 动态模板下载后填写并上传 | 不改列名即可补充；模板不携带凭据、不生成公式 |

逻辑测试覆盖归一化、批内/库内判重、投影去重与原始行去重的区别、保留集合和父图校验。集成测试使用经确认的专用测试库，覆盖跨绑定事务、并发判重、引用竞态和失败回滚。前端使用现有 Vitest/Playwright 覆盖加行表单、重导字段配置、引用错误与模板往返；新增分支按仓库规则做摘除式变异，确认对应断言能变红。

## 10. 留给实现者的决定

Action 路径/名称、字段的具体 DSL 类型、批写分片大小、错误码的现有枚举映射、组件拆分和 xlsx 写库版本，由实现者在不改变上述语义的前提下沿用仓库惯例。

不允许实现者自行改成：选项级去重代替原始行去重、仅进程锁、配置先保存后导入、补充被全量覆盖、被引用字段仅警告后删除。
