飞书数据源

审批表单的选项由这里出发。先确认每个数据源的状态、加密与默认语言，再点进详情核对选项。

1
在飞书审批后台配置控件
打开审批定义里的单选或多选控件，取值方式改成「使用外部选项」，自定义一个 Token 并记住它。
2
在这里建一个数据源
填数据源标识、显示名称，粘贴上一步的接口 Token。标识会进接口地址，建好之后不要再改。
3
把接口地址与 Token 填回审批后台
回到审批控件的配置页，粘回地址与 Token，让控件从这里取选项。
4
在多维表格配自动化推送选项
用 HTTP 节点带管理 Token 调写入接口，表格里增删一行，审批选项跟着变。
接口 Token 只在飞书那边显示一次。服务端只保存它的摘要，之后无法回显，请先复制到安全的地方。

删除数据源

删除后其下全部选项会被同时停用，且不可恢复。确认删除？

与「停用」的区别：停用只是让控件暂时取不到选项，随时可以再启用；删除不可恢复。

停用数据源

停用后，飞书审批中正在使用该数据源的控件会立即取不到选项——拉选项会拿到「40301 数据源已停用」，正在走流程的人当场看到空列表。

停用不删除任何数据：选项行原样留着，随时可以再启用恢复。要彻底清掉请用「删除」。

已知实现约束（方案 B · 紧凑目录）

  1. 列表按状态筛选当前服务端做不到：feishu_datasource.status 没声明 .filterable(true)，框架对筛选 fail-closed，会直接回「字段不允许筛选」。要真能用，需后端补第四处改动。
  2. 列表必须由前端显式传 order_by：list_datasources 没有默认排序兜底，不发就是无序分页，翻页会重复或漏行。
  3. 没有任何 Action 能按 source_key 取单个数据源。详情页头部现在靠导航态带过来，刷新或分享链接会丢；要稳就得再发一次带 where 的 list_datasources。
  4. 列头不画「按名称排序」箭头：title 只声明了 .searchable(true)，能搜但不能筛、不能排；整张表里只有 source_key 是 .sortable(true) 的。
  5. 「校验数据」按钮控制台做不到，本方案没有画它：唯一能校验的是 approval_options，它要拿数据源 Token 自校验，而服务端永远回不出明文 Token。
  6. 行上不显示选项数量与最后同步时间（后端不返回）。要显示，得给 list_datasources 加字段，或给 option 表补 updated_at。
  7. 角色判断走 catalog.actions 里有没有对应 operation_id —— 目录本身已按身份投影，前端不需要解析 JWT。
  8. 筛选在两个层级上不对称：详情页的选项能按 enabled 筛（option 表声明了 filterable），列表页的状态筛选是假的。两处画一样的筛选器会误导，所以本方案只在列表画。

以上是后端现状，不是本方案的设计取舍。
