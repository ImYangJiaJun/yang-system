停用数据源

停用后，飞书审批中正在使用该数据源的控件会立即取不到选项。

已知实现约束

这个方案在当前后端能力下踩到的边界。原型按真实能力画，没有假装。

  1. 1列表没有筛选器，是刻意的。给 status 做筛选需要后端先声明 .filterable(true)——未声明的字段服务端直接回「字段不允许筛选」。同理 title 只声明了 searchable(true)（能搜，不能筛也不能排），整个 feishu_datasource 里只有 source_key 是 sortable(true)，所以卡片上不出现任何排序入口。详情页的选项列表是反例：enabled 已声明 filterable，那边真能筛。
  2. 2列表分页必须由前端显式传 order_by。list_datasources 只遍历传入的 order_by，没有默认排序兜底；不发就是无序分页，翻页会重复或漏行。（list_options 有回退到 sort_order + option_id，是反例。）
  3. 3没有「按数据源标识取单个数据源」的 Action。详情页头部要么再发一次带 where 的 list_datasources，要么靠导航态传递——这个原型用的是内存导航态，刷新或把链接分享给别人会丢。
  4. 4卡片上没有选项数量，也没有最后同步时间。list_datasources 只回 source_key / title / encrypt_enabled / default_locale / status。要显示得给后端加字段（或给 option 表补一个可读的 updated_at 投影），或者逐源再调一次 list_options。
  5. 5「校验数据」按钮控制台做不到。唯一能校验的是 approval_options 端点，它要拿数据源 Token 自校验，而服务端只存 SHA-256 摘要、永远回不出明文。所以指引第 3 步只写「把值填回飞书后台」，不画这个按钮。
  6. 6角色判断走 catalog.actions 里有没有对应的 operation_id（目录本身已按身份投影），不需要前端解析 JWT。三个权限位是独立的：只有 feishu.datasource.read 而没有 feishu.option.read 时，卡片列表正常、点进详情选项区 403——见控制条「边界态」。
  7. 7选项区永远只读。没有任何新增、编辑、删除选项的 Action。这是架构决策（选项归多维表格管），不是还没做。
