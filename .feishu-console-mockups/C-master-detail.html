主从分栏 · 设计文档之外还要动的后端改动，以及本方案不敢画的东西

  1. 1左栏按状态筛选，后端目前做不到。本方案左栏只有搜索；若要补「全部 / 启用 / 停用」，需给 status 加 .filterable(true)——框架对筛选是 fail-closed，字段没声明就直接回「字段不允许筛选」。注意不对称：详情页选项按 enabled 筛是真的（option/table.rs 已声明），两边画一样的筛选器会误导。
  2. 2左栏列表必须由前端显式传 order_by。list_datasources 没有默认排序兜底（只遍历传入的 order_by），不发就是无序分页，翻页会重复或漏行。
  3. 3没有任何 Action 能按 source_key 取单个数据源。右栏头部要么再发一次带 where 的 list_datasources，要么靠导航态（本原型的 state.selected）传递——刷新或把链接发给别人就会丢选中态。
  4. 4「校验数据」按钮控制台做不到。唯一能自校验的是 approval_options，它要拿数据源 Token 去校验，而服务端永远回不出明文 Token（只存 SHA-256 摘要）。所以指引第 3 步只能是把值复制回审批后台，由飞书那边触发。
  5. 5左栏条目不能显示选项数量与最后同步时间（list_datasources 不返回，也没有任何 Action 返回同步时间）。右栏的「共 N 项」是合法的——它来自 list_options 的真实返回，不是猜的。
  6. 6身份判断只看 catalog.actions 里有没有对应 operation_id：目录本身已按身份投影，前端不需要解析 JWT。三个权限位相互独立，因此存在「有 feishu.datasource.read、没有 feishu.option.read」的组合——原型控制条里的「审计」就是它，表现为清单正常、详情 403。
  7. 7两处列表都不画排序箭头。title 只声明了 .searchable(true)（能搜、不能筛、不能排），feishu_datasource 里只有 source_key 是 .sortable(true) 的；画了箭头就得靠前端自己排。
