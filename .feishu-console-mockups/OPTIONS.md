# 四个原型 · 信息架构规格

共同底座见 `CONTRACT.md`（token、组件配方、文案、图标、角色规则）。
本文件只定义**四个原型彼此不同的部分**：信息架构。

四个方案都服务同一件事——**让人确认"飞书那边配的选项，这边真的通着"**。
它们的差别在于把这件事的**重心**放在哪里。

| | 重心 | 首页隐喻 | 最适合 |
|---|---|---|---|
| **A 卡片画廊** | 每个数据源是一个"东西" | 目录墙 | 文档原案，双方都能接受 |
| **B 紧凑目录** | 状态一眼扫完 | 台账 | 业务态（日常查看） |
| **C 主从分栏** | 看选项这件事要快 | 邮件三栏 | 业务态（频繁钻取） |
| **D 向导优先** | 第一次怎么配 | 装配线 | 运维态（低频配置） |

四个都必须在**同一个页面内**可切换到空/加载/错误态（见 CONTRACT §7），
且都要有真实的详情视图与对话框。

---

## A · 卡片画廊（文档原案）

**论点**：一个数据源是一个有边界的"东西"，值得占一块地方。
卡片本身就是它的身份牌——名称、标识、状态、两个属性。

### 有数据

```
┌ 飞书数据源 ───────────────────────────────  [+ 添加数据源] ┐
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 从飞书审批后台到多维表格，四步接起来          收起 ▴ │ │
│ │ ① 配控件  ② 建数据源  ③ 填回后台  ④ 配推送        │ │
│ └──────────────────────────────────────────────────────┘ │
│                                                          │
│ ┌────────────────────┐ ┌────────────────────┐ ┌────────┐ │
│ │ 报销事由分类    ⋯ │ │ 请假类型        ⋯ │ │ 采购归… ⋯│ │
│ │ expense-category   │ │ leave-type         │ │ purcha… │ │
│ │ ● 启用   🔒 加密    │ │ ● 启用             │ │ ● 启用  │ │
│ │ zh-CN              │ │ zh-CN              │ │ zh-CN   │ │
│ └────────────────────┘ └────────────────────┘ └────────┘ │
│ ┌────────────────────┐ ┌────────────────────┐ ┌────────┐ │
│ │ 供应商名录      ⋯ │ │ IT 资产分类     ⋯ │ │ 差旅城市│ │
│ │ vendor-list        │ │ it-asset-class     │ │ travel… │ │
│ │ ○ 已停用           │ │ ● 启用             │ │ ● 启用  │ │
│ │ zh-CN              │ │ en-US              │ │ zh-CN   │ │
│ └────────────────────┘ └────────────────────┘ └────────┘ │
└──────────────────────────────────────────────────────────┘
```

- 卡片整块可点 → `/feishu/datasources/:sourceKey`。
- 右上角 `⋯` 是下拉菜单（重命名 / 停用 / 删除），业务态**不渲染**这个按钮。
- 卡片**不加阴影**，`1px` 边框 + `rounded-xl`。
- 状态徽标在标题行右侧，用 tone 色（启用=positive，已停用=warning）。
- 栅格：`repeat(auto-fill, minmax(260px, 1fr))`，gap 16px。
- 业务态：`⋯` 消失，卡片右下角出现一个「查看选项」的次要提示，整体仍是可点整块。

### 空状态

指引**自动展开**（有数据时默认折叠），下面一块空状态：
标题「还没有数据源」+ 一句「先在飞书审批后台配好控件并拿到 Token，再回来建第一个」+
主按钮「添加数据源」+ 次按钮「怎么拿到 Token？」（展开第 1 步详情）。

## B · 紧凑目录

**论点**：这个页面的日常工作不是"管理很多数据源"，而是"确认某个数据源对不对"。
那就让所有数据源的状态在一屏里排完，像台账一样可扫。

### 有数据

```
┌ 飞书数据源 ───────────────────────────────  [+ 添加数据源] ┐
│ [🔍 搜索名称或标识      ]  [全部 ▾]        首次使用？ ▸  │
│ ──────────────────────────────────────────────────────── │
│ 名称              标识               状态     加密  语言  │
│ ──────────────────────────────────────────────────────── │
│ 报销事由分类      expense-category  ● 启用    🔒   zh-CN ⋯│
│ 请假类型          leave-type        ● 启用    —    zh-CN ⋯│
│ 采购归口部门      purchase-dept     ● 启用    🔒   zh-CN ⋯│
│ 供应商名录        vendor-list       ○ 已停用  —    zh-CN ⋯│
│ IT 资产分类       it-asset-class    ● 启用    —    en-US ⋯│
│ 差旅城市          travel-city       ● 启用    —    zh-CN ⋯│
│ ──────────────────────────────────────────────────────── │
│ 共 6 个数据源                        第 1 / 1 页  ‹  ›   │
└──────────────────────────────────────────────────────────┘
```

- 行整行可点 → 详情路由。
- 行高受 `--density-cell-y` 驱动（页头「密度」菜单能实时改），这是**这个方案的卖点**。
- `标识` 列用等宽字体。
- 筛选：`全部 / 启用 / 停用` 三档分段控件（不是下拉，因为只有三档）。
- 表头 sticky。
- 悬停整行 `bg-accent`；`⋯` 只在悬停/聚焦时出现（业务态永不出现）。
- 业务态：工具栏只剩搜索 + 筛选 + 指引；`+ 添加数据源` 消失。

### 空状态

同 A 的文案，但**放在表格位置**，且指引默认展开。
搜索框与筛选器在空状态下**不渲染**（避免"搜了个空"）。

## C · 主从分栏

**论点**：看数据源不是终点，看它下面**有哪些选项**才是。
既然详情是高频动作，就把它和列表放在同一屏，省掉一次导航。

### 有数据

```
┌ 飞书数据源 ────────────────────────────────────────────────┐
│ ┌ 数据源 (6) ──────┐ ┌ 报销事由分类 ────────────────────┐ │
│ │ [🔍 搜索        ]│ │ expense-category  ● 启用  🔒 加密 │ │
│ │                  │ │ zh-CN                    [⋯ 更多] │ │
│ │ ▌报销事由分类    │ │ ──────────────────────────────── │ │
│ │   expense-categ… │ │ 选项 8 个     只读 · 由多维表格维护 │ │
│ │  请假类型        │ │ ┌──────────────────────────────┐ │ │
│ │   leave-type     │ │ │ 差旅费            默认  启用 │ │ │
│ │  采购归口部门    │ │ │ 办公用品                启用 │ │ │
│ │  供应商名录  ○   │ │ │ 业务招待                启用 │ │ │
│ │   IT 资产分类    │ │ │ 培训费                  启用 │ │ │
│ │  差旅城市        │ │ │ 通讯费                  停用 │ │ │
│ │                  │ │ └──────────────────────────────┘ │ │
│ │ [+ 添加数据源]   │ │                                  │ │
│ └──────────────────┘ └──────────────────────────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- 左栏固定 280px，独立滚动；右栏自适应。
- 左栏选中项：`bg-accent` + 左侧 2px 竖条（`--primary`）。
- 已停用的数据源在左栏名字后跟一个 `○`，并在选中时右栏顶部出现一条中性说明条。
- 右栏空选时：显示「从左边选一个数据源」+ 图标（不是错误态）。
- 路由：`/feishu/datasources?source=purchase-dept`（查询参数，`BusinessPage` 有先例），
  这样前进/后退仍可用，且不必新增带参路由范式。
- 业务态：`+ 添加数据源` 与 `[⋯ 更多]` 都不出现。
- **窄屏（<900px）**：塌成单栏——先列表，选中后整屏显示详情并带「‹ 返回列表」。

### 空状态

左栏显示空状态提示，右栏显示指引的完整四步（比 A/B 更有空间可放，这里可以把指引做扎实）。

## D · 向导优先

**论点**：这个控制台 90% 的使用价值发生在一个人的**第一次**配置上。
与其在页面顶部贴一段可折叠的说明，不如把说明变成**流程本身**：
新用户进来就是一条四步装配线，配完一个之后它自动退化成台账。

### 首次进入（还没有数据源）

```
┌ 飞书数据源 ────────────────────────────────────────────────┐
│  ①───②───③───④                                            │
│ 飞书审批  建数据源  填回后台  配推送                        │
│  ─────────────────────────────────────────────────────────│
│                                                            │
│  第 1 步 · 在飞书审批后台配置控件                          │
│                                                            │
│  打开你要用的那个审批定义，找到单选或多选控件，             │
│  把取值方式改成「使用外部选项」，然后自定义一个 Token。      │
│                                                            │
│  ⚠ 这个 Token 只在飞书那边显示一次。服务端只保存它的        │
│    摘要，之后无法回显——请先复制到安全的地方。              │
│                                                            │
│  ┌ 要填的东西 ────────────────────────────────────────┐   │
│  │ 控件类型     单选 / 多选                            │   │
│  │ 取值方式     使用外部选项  ← 不是「自定义选项」      │   │
│  │ 自定义 Token 随便起，记住它                          │   │
│  └────────────────────────────────────────────────────┘   │
│                                                            │
│                                    [我配好了，下一步 →]    │
│  ─────────────────────────────────────────────────────────│
│  已经有数据源了？ 跳过向导 →                                │
└────────────────────────────────────────────────────────────┘
```

- 步骤条是**真序列**，所以用编号是恰当的（不是装饰）。
- 第 2 步就是 CONTRACT §7-4 的新增表单，内联在流程里而不是对话框里。
- 第 3 步给一个「校验数据」按钮——但注意：**这个能力当前后端没有**
  （8 个 Action 里没有校验接口）。原型里必须把它标成「待后端补」并做成
  一个占位按钮，不要假装它能用。或者退化为「把上面填的值复制回去」的清单。
- 第 4 步是指引的最后一段 + 一个可复制的 `Authorization: Bearer …` 片段。

### 配完之后（已有数据源）

向导收起成页头右上角的一个「配置向导」次要按钮；主区域退化为**方案 B 的紧凑目录**。
也就是说 D = B + 首次进入时多一层向导。这样它不是一个只能看一次的花架子。

### 空/加载/错误

空状态就是向导第 1 步。加载态在向导容器内显示骨架。错误态在内联表单下方显示错误条。

## 建造要求（四个方案通用）

1. 严格按 `CONTRACT.md`：token 逐字、组件配方逐字、文案逐字、图标只用白名单里的。
2. **演示控制条**：在每个原型**页面右上角之外**（即固定悬浮在视口底部或顶部）放一条
   明显的"原型控制"条，用来切换：空 / 有数据 / 加载 / 错误、运维态 / 业务态、明暗。
   它必须一眼看出不是产品的一部分（用虚线边框 + 「原型控制」标签 + 中性底）。
3. 点击卡片/行 → 进入详情；对话框、下拉菜单都要能真的打开；`Esc` 能关。
4. 用真实数据（CONTRACT §6），不要 lorem，不要 `xxx`。
5. 单文件、无外部依赖、`file://` 可打开。
6. 代码里不要写 `TODO` 注释。结构清晰、缩进统一、无未闭合标签。
7. 详情页/右栏要如实体现**只读**：选项区顶部有一行说明「选项由多维表格自动推送，控制台只读」，
   且**没有任何增删改按钮**——这是文档的非目标，必须显式呈现，否则会误导评审。
8. 删除确认对话框必须用 CONTRACT §6.4 的原文，并说明会连带停用其下选项。
