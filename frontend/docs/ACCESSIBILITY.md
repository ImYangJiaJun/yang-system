# 前端无障碍验收合同

## 支持基线

正式登录、角色选择和模块操作关键旅程以 WCAG 2.2 AA 为自动门禁目标。当前仓库使用固定版本 `@axe-core/playwright@4.12.1`，扫描 `wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa` 和 `wcag22aa` 标签。

自动门禁位于 `e2e/accessibility.spec.ts`，由默认 `pnpm e2e` 执行，因此也进入 `python scripts/run_ci.py full` 和 GitHub quality job。用例必须：

- 对登录页、角色页、正式模块页和打开后的表单对话框运行 axe，违规数组必须为空；
- 只用 Tab、键入、Enter 和 Escape 完成登录、选择角色、进入模块、打开并关闭操作；
- 断言关键控件具有可见的 3px 焦点环；
- 断言对话框有可访问名称，打开后焦点进入关闭按钮，Escape 关闭后焦点回到触发按钮。

## 组件实现约束

- 页面地标必须有唯一且准确的可访问名称，不得把 `role="list"` 的组件包在不合法的子节点结构中。
- 图标按钮必须提供 `aria-label`；状态变化需要可感知名称或状态属性。
- 对话框标题必须成为对话框的可访问名称，并显式管理初始焦点与触发点恢复。
- 普通文本对比度不得低于 4.5:1；大号文本和非文本控件按对应 WCAG 阈值验收。
- 键盘焦点不能只依赖浏览器或组件库默认样式；全局双层焦点环必须同时适配浅色和深色背景。

## 自动化边界

axe 和 Playwright 只能证明被覆盖状态中的可自动检测规则与键盘行为，不能替代屏幕阅读器、缩放、Windows 高对比度、语音控制和真实辅助技术人工验收。发布前若目标用户或采购规范要求这些能力，应在目标浏览器和辅助技术矩阵上补充人工记录；不得把本自动门禁外推为完整合规认证。
